1. Overview

All endpoints live under /api/hr/… except the Accounting inbox under /api/accounting/hr-handoffs.

2. How to call the HR API

Authentication & company

  • Send Authorization: Bearer <JWT> from the normal login.
  • Every HR controller is tenant scoped: the company comes from the token (companyId claim) and the request runs inside that company's Oracle schema.
  • Super admin must choose one company with X-Company-Id or X-Company-Code (not both).
  • Where an endpoint still asks for companyId, it must equal the token company, otherwise 403.

Permissions

  • Each endpoint declares screen:feature (e.g. hr-leaves:approve), granted per user/role and per branch.
  • SELF endpoints also work for an employee without the grant, but only for his own linked employee record.
  • Users see only employees and data of branches they are granted (admins see all branches).
  • Identity, bank and salary fields need extra field permissions; otherwise they come back empty.
  • Approvers can never approve their own request (self-approval guard).

Response envelope

{
  "success": true,
  "statusCode": 200,
  "message": "Employees retrieved successfully.",
  "data": { ... },
  "errors": null,
  "timestamp": "2026-12-01T08:00:00Z",
  "traceId": "00-..."
}

Status codes & conventions

200Success
202Accepted (e.g. punch stored, processing later)
400Validation / business rule failed (message explains)
401No / expired token
403No permission, other branch, other company, or employee code not visible
404Record not found in your scope
409Version conflict (If-Match), duplicate event, or disabled legacy endpoint
  • Dates: yyyy-MM-dd; pay period: yyyy-MM.
  • Updates on shifts, roster, assignments, org and branch location need the If-Match version header.
  • Grants, payments and punches use idempotency/event keys: repeat safely with the same key.

3. End-to-end HR business cycle

How the modules connect in a real company, in the order they are used.

1 · Company setup (once)Time zone, branch GPS, attendance policy, work calendar & holidays, shifts, departments & positions, salary components, leave settings/types/policies, payroll policies, EOS policy, Accounting posting accounts.
2 · HireCreate employee (or Excel import) → salary structure → dependents → link login user → assign base shift → generate roster → yearly leave grant.
3 · DailyMobile check-in/out or device punches → processing → day status. Short leaves and leave requests submitted and approved. Corrections for missing punches.
4 · During the monthLoans/advances requested, approved and funded by Accounting. One-off adjustments and overtime adjustments approved and posted.
5 · Month endReview timesheets → calculate payroll → explain/compare → approve (different user) → handoff to Accounting → JV posted → payment confirmed → employees read payslips → close period.
6 · Year endLeave year-end close draft → post → cash-out of excess days (becomes payroll adjustments).
7 · ExitEnd of service calculate → approve (employee TERMINATED) → payout request → Accounting pays.

Business rules enforced by the code

  • Employee code unique in the schema; national ID unique (shared lock with import).
  • Department must be active and belong to the employee's branch; position must belong to the department; manager must be active and no reporting cycle.
  • Sensitive groups (identity, bank, salary) are hidden or read-only without the matching field permission.
  • Edits that affect dates covered by an approved payroll are blocked (payroll period lock).
  • Excel import is one transaction: any row error rolls back everything; preview shows INSERT/UPDATE and salary impact.
  • Termination fields and TERMINATED status are rejected in create/update/import.

Statuses

Raw event:PENDING (IsProcessed=false)→PROCESSED→IGNORED  Evidence is never deleted.
Correction:PENDING→APPROVED→REJECTED

Business rules enforced by the code

  • Mobile requires EventId; the same EventId with different content returns 409; replays return the original receipt.

  • Correction: reason required, no future times, 409 if the day changed after the request.
  • No self-approval; periods locked by approved payroll cannot change (raw evidence kept pending with reason).

Business rules enforced by the code

  • A posted year-end close locks the cycle for grants, requests and corrections.
  • Short leave beyond the monthly paid quota is deducted from a leave type or salary, per policy.
  • No self-approval.

7. Known limitations (from HR_MASTER.md)

  • Bank file export, direct GL posting/reversal and the legacy posting-config save return 409 by design: Accounting owns posting and payment.
  • DELETE /api/hr/employees/{code} always refuses — terminate through End of Service.
  • Some endpoints still require companyId (query or body); send the token company or you get 403 (planned removal, F6).
  • No update/delete yet for salary components, work calendars/holidays and payroll policies; no GET-by-id for leave requests, loans, advances and corrections; no reject for loans/advances (F16).
  • Payslip is JSON only (no PDF). No branch daily attendance report yet (F9).
  • FORMULA salary components are rejected (deferred). Multi-currency payment batches and the real bank file are deferred.
  • Code changed after the last full test run (13 Nov); behaviour here reflects the source, not a tested release.
