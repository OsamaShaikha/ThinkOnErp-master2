▶ Architecture Overview

The audit system captures every state-changing operation through a layered pipeline: MediatR behaviors intercept CQRS commands, an ADO.NET interceptor catches raw SQL, events flow through a resilient channel-based logger, and fallback to the filesystem when the database is unavailable.

▶ Auto-Capture Pipeline

MediatR PipelineBehavior
AuditLoggingBehavior<TRequest, TResponse>
Intercepts all commands (name ends with “Command”). Captures request state before execution and response/exception after. Runs fire-and-forget to never block the pipeline. Extracts entity type from command name (CreateUserCommand → User) and determines action: Create/Add → INSERT, Update/Change/Assign → UPDATE, Delete/Remove → DELETE.
ADO.NET Interceptor
AuditCommandInterceptor
Wraps AuditableOracleConnection / AuditableOracleCommand to intercept raw SQL INSERT / UPDATE / DELETE. Extracts table name and action type. Skips audit tables (SYS_AUDIT_LOG, SYS_AUDIT_LOG_ARCHIVE) to prevent infinite recursion.

▶ FileSystemAuditFallback

When the database is unavailable (circuit breaker open), audit events are written to JSON files on disk and replayed when the DB recovers.

Storage Path
logs/audit-fallback/
Configurable via SYS_SETTINGS CODE 5 or appsettings
File Naming
audit_fallback_{yyyyMMdd_HHmmss}_{guid}.json
Single or batch files
Rotation
Max 100 MB total
Oldest files → archive/ subdirectory, 20% buffer maintained
Replay
Max 3 attempts
Failed files → error/ subdirectory
Concurrency
SemaphoreSlim (singleton)
Separate locks for write and replay
Last Resort
Windows Event Log / stderr
If even file write fails

Write Flow

  1. Acquire write SemaphoreSlim (singleton lock)
  2. Check directory availability (falls back gracefully if unavailable)
  3. Trigger file rotation if total size exceeds 100 MB
  4. Create FallbackAuditEntry or FallbackAuditBatch wrapper (includes EventType, WrittenAt, ReplayAttempts)
  5. Serialize to indented JSON and write to disk
  6. Update metrics (_totalEventsWritten)
  7. On failure: log error, increment _failedWrites, attempt TryWriteToSystemLog
  8. Release lock

▶ Security & Integrity

Tamper Detection

  • HMAC-SHA256 integrity hash stored in Metadata.integrity_hash
  • Hash covers all audit fields + a secret key
  • IAuditLogIntegrityService verifies individual entries and batches
  • DetectTamperingAsync scans date ranges and triggers alerts

Field-Level Encryption

  • AES-256-GCM (authenticated encryption)
  • Thread-safe via SemaphoreSlim
  • Encrypts sensitive fields before storage
  • Decrypts on read for authorized users

Data Masking

  • Sensitive fields masked before logging (passwords, tokens, PII)
  • Masking happens in the AuditLogger before enqueueing

RBAC Filtering

  • SuperAdmin: sees all audit logs across all tenants
  • CompanyAdmin: sees logs for their company only
  • User: sees logs for their own actions only
