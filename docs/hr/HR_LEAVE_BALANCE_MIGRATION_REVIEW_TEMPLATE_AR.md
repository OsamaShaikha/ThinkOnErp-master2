# نموذج مراجعة ترحيل أرصدة الإجازات القديمة

يُنسخ هذا النموذج مرة لكل شركة/مخطط قبل إنشاء مسودة `LEV-16`. الاختيار التشغيلي المعتمد هو **توزيع يدوي بالمراجعة**: لا تُرحّل قيمة مركبة أو دورة تلقائياً، ولا يُنشر شيء قبل مطابقة المصدر واعتماد المسودة.

## مطابقة كل رصيد مصدر

أنشئ صفاً لكل رصيد مصدر **ولكل دورة هدف**. عند توزيع رصيد مصدر على أكثر من دورة، يجب أن تتطابق مجاميع الصفوف مع المصدر لكل مكوّن على حدة.

| معرّف الرصيد | الموظف | نوع الإجازة | دورة المصدر من/إلى | مستحق المصدر | مستخدم المصدر | مرحّل المصدر | دورة الهدف من/إلى | المخصص مستحق | المخصص مستخدم | المخصص مرحّل | فرق المستحق | فرق المستخدم | فرق المرحّل | مرجع/سبب التوزيع | مراجع HR |
|---|---|---|---|---:|---:|---:|---|---:|---:|---:|---:|---:|---:|---|---|
|  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |  |

معيار المراجعة: كل فرق يساوي صفراً بدقة التخزين `0.0001`، ومجموع كل تخصيصات المصدر يساوي قيمة المصدر لكل مكوّن؛ لا تُسوّى الفروق بين المستحق والمستخدم والمرحّل بعضها ببعض.

## بوابات ما قبل إعداد المسودة

- [ ] جرى استخراج كامل أرصدة الشركة المعنية، ومطابقة العدد والمجموع بحسب الموظف/النوع/الدورة.
- [ ] راجع مالك بيانات HR كل تخصيص يدوي وكل تقسيم بين دورات مستهدفة.
- [ ] لا يوجد طلب إجازة معلق أو طلب معتمد يتقاطع مع حد دورة الترحيل.
- [ ] لا توجد دورة مقفلة أو حركة تابعة تمنع الترحيل أو العكس.
- [ ] إعداد بداية سنة الإجازة الحالية والهدف موثق، مع أثره على الموظفين والدورات.
- [ ] نسخة البيانات قابلة للاستعادة، وجرّبت الاستعادة في بيئة مناسبة؛ رقم النسخة لا يكفي وحده.
- [ ] تم تأكيد مخطط الشركة المقصود صراحة؛ لا تستخدم DEV_TEMPLATE بديلاً عن موافقة tenant.

## مراجعة المسودة قبل النشر

| الحقل | القيمة |
|---|---|
| رقم المسودة / API id |  |
| بصمة المصدر |  |
| عدد أرصدة المصدر |  |
| عدد أسطر التخصيص |  |
| مجموع المكونات قبل / بعد لكل عملة؟ | أيام — المستحق: ___ / المستخدم: ___ / المرحّل: ___ |
| تغييرات إعداد السنة | من: ___ / إلى: ___ |
| حالات رفض أو استثناء تمت مراجعتها |  |

- [ ] تمت مراجعة كل سطر في المسودة مقابل جدول المطابقة أعلاه.
- [ ] أُعيدت معاينة المصدر ولم تتغير بصمته منذ إعداد المسودة.
- [ ] أعاد HR المراجع قراءة المسودة من API قبل POST؛ لم يعتمد على نسخة شاشة أو ملف قديم.
- [ ] وافق مالك HR على النشر بعد مراجعة مستقلة.
- [ ] لا توجد طلبات أو إقفالات جديدة منذ المعاينة؛ يعيد النظام التحقق عند POST.

## اعتماد ما بعد النشر وخطة الرجوع

| الحقل | القيمة |
|---|---|
| رقم الحركة/المسودة المنشورة |  |

- [ ] لم يُنفذ POST إلا بعد الاعتمادين أعلاه.
- [ ] طوبقت أرصدة الهدف وحركات `MIGRATION_OUT/IN` وإعداد السنة مع المسودة المنشورة.
- [ ] حُفظت نسخة هذا النموذج مع تقرير المصدر والبصمة وسجل التدقيق.
- [ ] خطة الرجوع هي endpoint `reverse` للمسودة نفسها، بشرط عدم وجود حركة تابعة؛ لا حذف يدوي للحركات أو إعادة ضبط الأرصدة مباشرة.

**حدود هذا النموذج:** لا ينفذ مزامنة مخطط أو DDL أو cutover أو عكساً تلقائياً. اختبار Oracle متعدد الجلسات ومزامنة tenant واعتماد المالك والنشر المراقب أدلة مستقلة يجب تسجيلها في خريطة HR.
