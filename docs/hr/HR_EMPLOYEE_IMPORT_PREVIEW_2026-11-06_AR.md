# EMP-10 — معاينة أثر استيراد الموظفين

6 نوفمبر 2026. يمتد POST /api/hr/employees/import/validate الموجود، بنفس ملف multipart/form-data وصلاحية hr-employees/import، دون حفظ أو تغيير عقد طلب الاستيراد الفعلي.

## ناتج المعاينة

EmployeeImportResultDto يضيف PreviewGeneratedAtUtc وPreviewRows. لكل صف صالح لتدقيق الملف:

- RowNumber وEmployeeCode وAction=INSERT/UPDATE وRequiresUpdateExisting.
- SalaryChange=NOT_PROVIDED/UNCHANGED/NEW_VERSION/INVALID وتاريخ النسخة المقترحة SalaryEffectiveFrom. التكرار بنفس الراتب لا يقترح نسخة جديدة؛ لا إغلاق للهيكل السابق في المعاينة. تاريخ راتب جديد قبل التعيين مرفوض في المعاينة أيضاً.
- AffectedFrom: أقدم تاريخ بين التعيين المطلوب والقديم وتاريخ الراتب المطلوب وكل الهياكل القديمة، مثل حارس المدخلات الحالي. الاستيراد يعدل ملفاً غير مؤرخ؛ الأثر مفتوح النهاية، وليس محصوراً بتاريخ الراتب الجديد.
- AffectedPeriods: رمز/بداية/نهاية/حالة فترات الشركة التي تنتهي من تاريخ الأثر فأحدث، وعلم HasApprovedPayroll دون مبالغ أو معرفات المسير.
- HasUnmappedApprovedPayroll وBlockingReasons: CLOSED_PAYROLL_PERIOD أو APPROVED_PAYROLL أو UNMAPPED_APPROVED_PAYROLL. يضاف PAYROLL_INPUT_BLOCKED إلى أخطاء الصف ويصبح IsValid=false عند الحظر.

INSERT/UPDATE تصنيف للعملية المقترحة، وليس كشف فرق كل حقل؛ الحفظ العام يحدّث الملف وتدقيقه. لا يُسمى الصف UNCHANGED لمجرد تطابق الراتب. InsertedCount/UpdatedCount تبقيان عدادات الحفظ الفعلي ولا تُملآن من المعاينة.

الفشل في قراءة الملف أو الحقول المطلوبة لا ينتج أثر صفوف مفترضاً. الصف المخفي أو الفرع غير المخول لا يعيد بيانات مخزنة أو فترات؛ ينتج EMPLOYEE_NOT_EDITABLE أو IMPORT_SCOPE_UNAVAILABLE. التحقق من حدود النص الفعلية وتطبيع الملف السابق مستمران. تُعرض حقائق الحظر للتوابع المالية التاريخية للموظف المرئي حتى إن خرج فرع المسير القديم من نطاق عرضه، دون عرض بيانات المسير نفسه.

## حدود الثقة والحفظ

المعاينة استرشادية غير محجوزة عند PreviewGeneratedAtUtc. لا توجد موافقة أو رمز يسمح بتجاوز الأقفال: الاستيراد يقرأ الملف ويعيد التحقق من الشركة/الفروع والفترات/التوابع داخل معاملته المملوكة. أُضيف رفض الفرع غير المخول قبل استعلام الحماية، وحماية الاعتمادات القديمة بلا PayrollPeriod مقابل إلى Excel كما في الإنشاء المباشر، بما فيها توابع الموظف التاريخية؛ لا يُفتح مسير أو تُخمن فترته.

امتداد [EMP-12](HR_EMPLOYEE_SALARY_METADATA_2026-11-06_AR.md) يتطلب عملة/طريقة دفع صريحتين لأول هيكل، ويعيد CurrencyCode/PaymentMethod المحسومتين في معاينة الراتب الصحيح، ويتحقق من الكتالوج وسعة التخزين قبل خطة الإنشاء. الملف القديم يورّث السابق، ولا صفحات واجهة ضمن هذا النطاق. لا طلب تنفيذ محفوظ في PreviewRows ولا تعديل بصمات/رواتب أصلية.

## التحقق

اختبارات قواعد المعاينة: INSERT/UPDATE، طلب updateExisting، تاريخ الراتب، عدم تغيير الملف/الهيكل، السبب المالي، الفرع/الموظف المخفي، وبقاء الحارس مانعاً إذا تغيرت الظروف بعد معاينة ناجحة. HTTP محلي مع ملف XLSX حقيقي وقارئه وخدمة المعاينة والمستودع يثبت المعاينة داخل الفرع ورفض أثر فرع غير مخول؛ توجيه العميل InMemory تجريبي، وليس Oracle HTTP.

--verify-employee-import-preview يختبر SQL فترات/اعتماد/حظر وإخفاء الفرع على Oracle داخل fixture متراجع عنه، ويتحقق من غياب فترته ومسيريه وسطره. بعده يختبر رفض معاملة الاستيراد المملوكة قبل callback عند وجود اعتماد أصلي بلا فترة، دون إدخال موظف أو تغيير المعتمد الأصلي. إعادة فحص59 جدولاً أصلياً بعد fixtures ضمن emp10-preview-preservation-after.log. الأعداد النهائية في HR_ROADMAP_AR.md.

لا DDL أو مزامنة عميل أو نشر؛ التزامن الشامل والاستيراد الناجح عبر Oracle HTTP وقبول واجهة المستخدم مستقلان.
