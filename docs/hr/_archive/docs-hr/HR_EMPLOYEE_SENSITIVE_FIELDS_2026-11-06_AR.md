# EMP-04 — صلاحيات حقول الموظف الحساسة

6 نوفمبر 2026. فصل داخل مسارات إدارة الموظف الحالية، باستخدام SYS_FEATURE وSYS_SCREEN_FEATURE ومنح المستخدم/الدور والفروع الموجودة. لا دور HR جديد أو منح تلقائية. لا تغيير جداول أو بصمة الرواتب.

## الميزات والنطاق

| المجموعة | العرض | التعديل | الحقول |
|---|---|---|---|
| الهوية | view-identity | edit-identity | NationalId/Nationality/PassportNumber/DateOfBirth/Gender/MaritalStatus/Email/Phone/SscNumber/TaxExemptionCount/IsHighRiskRole/UserId، والمعالون في التفاصيل |
| البنك | view-bank | edit-bank | BankName/BankAccountNumber/BankIban |
| الراتب | view-salary | edit-salary | BasicSalary في الملخص وActiveSalaryStructure وتفاصيله |

الميزات على شاشة hr-employees، إضافة إلى صلاحية العملية الأصلية. جميع المنح محدودة بالفرع، والرفض الصريح يتقدم على الدور وفق القواعد الحالية؛ النظام/الشاشة/الميزة غير الفعالة أو غير المسجلة لا تمنح وصولاً. المشرف الإداري الموثوق يحتفظ بصلاحياته الحالية؛ ادعاء isAdmin في token لا يحول المستخدم العادي إلى إداري. UserId لا يُعدّل عبر مجموعة الهوية؛ مسار الربط الإداري EMP-13 مستقل.

## القراءة والكتابة

GET employees وGET employees/{code} وردود الإنشاء/التعديل تحجب الحقول غير المسموحة بقيم null وتخفي قائمة المعالين عند غياب عرض الهوية، مع fieldVisibility: identity/bank/salary/editIdentity/editBank/editSalary. القائمة الفارغة/القيمة null المحجوبة لا تعني عدم وجود البيانات. BranchId أضيف للملخص لتحديد النطاق. البحث بالهوية/الهاتف/البريد لا يحسب صفاً لا يملك المستخدم عرض هويته؛ بحث الرمز والاسمين مستمر.

| المسار | الضوابط الإضافية |
|---|---|
| POST employees | edit-identity؛ edit-bank عند تزويد بيانات بنك؛ الرد حسب حقوق العرض |
| PUT employees/{code} | استبدال كامل: edit-identity وedit-bank على الفرع الحالي والمطلوب؛ لا إعادة إرسال حقول محجوبة افتراضياً |
| PUT employees/{code}/work-profile | edit العام؛ أسماء وحقول عمل/تنظيم وحالة فقط، وبقية الملف من الصف بعد القفل |
| PUT employees/{code}/bank | edit العام وedit-bank فقط؛ جميع حقول البنك الثلاثة مطلوبة وnull مسح صريح |
| PUT employees/{code}/identity | edit العام وedit-identity فقط؛ جميع حقول مجموعة الهوية مطلوبة؛ البنك والعمل من المصدر |
| نقل فرع عبر ملف كامل/عمل | تعديل المجموعات الثلاث في الفرعين؛ تغير الفرع ينقل نطاق بيانات الموظف |
| إضافة/حذف المعال | edit-identity على فرع الأب بعد القفل؛ الإضافة تتطلب view-identity أيضاً لأنها تعيد المعال |
| GET salary-structure | view-salary مع view العام |
| POST salary-structure | edit-salary وview-salary مع صلاحية العملية الأصلية |
| export | صلاحية export وثلاث ميزات العرض لكل صف؛ عند غياب حق صف يُرفض الملف كله، دون ملف جزئي قابل لإعادة استيراد يمحو الحقول |
| import/validate وimport | صلاحية import والميزات الست في المصدر والهدف؛ قبل العمل ثم عند معالجة الصفوف بعد القفل؛ الرفض EMPLOYEE_FIELD_PERMISSION_REQUIRED |

DTO العمل والبنك والهوية ترفض الحقول الإضافية بدلاً من تجاهلها. لا يمكن تمرير NationalId أو UserId ضمن ملف العمل أو حقول بنك ضمن الهوية. تعديل مجموعة لا يمنح عرضها؛ الرد محجوب إذا غاب حق العرض. التعديل المحدود ينسخ بقية الملف من الصف المحمي ويعيد استخدام تطبيع/تدقيق EMP-01 وأقفال EMP-05؛ لا تجاوز CLOSED أو المسير المعتمد، ولا نموذج ملف مؤرخ جديد.

أخطاء تكرار الهوية لا تعيد القيمة المخزنة؛ هذا مهم عند تعديل عمل عام لملف قديم ذي هوية مكررة.

## الربط بالخدمة والتجهيز

EmployeeFieldAccess نطاق طلب يبدأ بالرفض. HrAccessFilter يحتاجه إلزامياً، ويملؤه من قاعدة الصلاحيات؛ التطبيق يسجله scoped وتستعمله الخدمة والمستودع نفسه. الخدمة تعيد التحقق في callback المحمي، لا تعتمد على DTO مرئي قبل القفل. البحث يطبّق منح الهوية قبل Count/الترقيم.

الإنشاء اليدوي للخدمات دون هذا المكوّن محجوز للمهام الداخلية الموثوقة/أداة التحقق القديمة، وليس نمط تهيئة HTTP. حقول API لا تقبل مكوّن الصلاحيات من العميل. لا يغيّر الحجب كيان الموظف أو بصمة المسير عند القراءة.

EmployeeFieldPermissionCatalog.EnsureAsync يجهز ست ميزات وروابط الشاشة دون مستخدم/دور/عضوية أو منح إيجابية، ويُستدعى من SeedData عند وجود شاشة hr-employees فعالة؛ لا ينشئ الشاشة/النظام الأساسيين المفقودين أو يفعلهما ضمناً. لا يعيد تفعيل ميزة موجودة معطلة. تجهيز هذا الكود لا يثبت مزامنة كتالوج كل عميل. وجد الفحص أن DEV_TEMPLATE لا يحتوي شاشة hr-employees مسجلة؛ فحص Oracle أنشأ كتالوجاً ومستخدماً ومنحاً اختبارية داخل transaction ثم تراجع عنها، ولم يثبتها دائماً.

## التحقق والحدود

الأدلة emp04-fields-hr.log وemp04-fields-api.log وemp04-fields-oracle.log وemp04-fields-preservation-after.log. تغطي المنح المستقلة والفروع ورفض الدور، حجب الرد والبحث، استبقاء بيانات العمل، كتابة كل مجموعة دون الأخرى، فحص الصلاحية داخل الحارس، Excel، وسحب الحق في الطلب التالي.

HTTP محلي فعلي مع JWT/MVC/الفلتر والخدمات وXLSX يستخدم توجيه adapters وInMemory؛ لا Oracle HTTP. Oracle يثبت SQL صلاحيات الميزات/الفروع والبحث، وتعديل العمل والبنك والهوية بالحارس الحقيقي، ثم rollback واستعادة قيم الموظف والميزات/الشاشة/النظام وإزالة مستخدم الاختبار وعضويته ومنحه. المقارنة المستقلة59 جدولاً أصلياً بعده مطلوبة ومثبتة في الخطة عند اكتمالها.

لا DDL أو نشر أو مزامنة عملاء أو منح دائمة. تعديل العميل وتعيين المنح لكل شركة قبل النشر ضمن [عقد الانتقال](HR_EMPLOYEE_FIELDS_CLIENT_MIGRATION_2026-11-06_AR.md) وOPS-03/09. صلاحيات مسيرات الرواتب/تصدير البنك المالية الموجودة مستقلة؛ هذا نطاق إدارة الموظفين، وليس تدقيق خصوصية لكل ERP أو سجلاته.
