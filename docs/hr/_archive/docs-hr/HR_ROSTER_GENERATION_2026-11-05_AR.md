# SHIFT-05 — توليد الجدول

5 نوفمبر 2026. المسار `POST api/hr/employees/{employeeCode}/shift-days/generate`، بصلاحية `hr-attendance/configure` دون كتابة ذاتية. الجسم `{ "from": "2026-12-01", "to": "2026-12-31" }`؛ التاريخان مطلوبان وشاملان، والحد التشغيلي للطلب 366 يوماً. النتيجة 200 داخل ApiResponse وتحتوي Created/Updated/Unchanged/PreservedManual/Unscheduled.

يولد من الإسنادات الفعالة، المؤقت قبل الأساسي، وبنفس قواعد المعاينة المشتركة AssignmentShiftSelection. يحفظ يوم العمل أو الراحة الصريحة بمصدر GENERATED، ولا يحوّل عدم الجدولة إلى راحة. يحافظ على جميع أيام MANUAL بما فيها غير الفعالة؛ تعديل اليوم المولد يدوياً عبر SHIFT-04 يحوله إلى MANUAL ويحميه من التوليد اللاحق.

إعادة نفس الطلب لا تنشئ صفوفاً أو تغير التدقيق إذا تطابقت النتيجة. يُعاد تفعيل GENERATED غير الفعال عند توفر إسناد، ويُحدّث الشفت/الراحة عند اختلاف الخطة. إذا لم يعد هناك إسناد، يعطّل GENERATED القديم ويحفظه؛ لا يحذفه ولا يخمن إسناداً. تغييرات الإسنادات نفسها ما زالت تخضع لحماية SHIFT-03، بما فيها اليومي الفعال.

العملية ذرية في معاملة ReadCommitted: أقفال فترات الرواتب ثم الموظف ثم أيامه بترتيب المعرف ثم التعريفات بترتيب الرموز. تُحمّل الإسنادات والأيام وتُخطط النتيجة قبل أي حفظ؛ التعارض في آخر يوم يرفض الدفعة كاملة. قفل التعريف مشترك مع الكتالوج. كل نطاق الطلب محمي من الفترات المقفلة والمسيرات المعتمدة حتى لو كانت النتيجة دون تغيير؛ الحضور يحمي الأيام التي ستتغير فقط. لا If-Match للدفعة؛ يُحسب الناتج من الحالة المقفلة الحالية، ولا تُقبل خطة أو نوع مصدر من العميل.

نجح بناء API و183 اختباراً محدوداً (11 حالة جديدة للتوليد)، وفحص Oracle داخل rollback: عمل/راحة من مؤقت فوق الأساسي، إعادة دون كتابة، حفظ اليدوي غير الفعال والاستثناء اليدوي، رفض حضور والتعارض المتأخر دون كتابة جزئية، فترة مقفلة وعزل ذاتي. تحقق من إزالة كل بيانات التجربة ومطابقة 59/59 جدولاً أصلياً. لا اختبار جلستين متزامنتين أو HTTP فعلي؛ لا DDL أو منح أو مزامنة عميل أو نشر تطبيق. قد تستهلك التجربة أرقام identity.
