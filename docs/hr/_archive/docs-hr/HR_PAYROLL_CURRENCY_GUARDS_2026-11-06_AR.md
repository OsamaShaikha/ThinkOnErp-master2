# حماية تجميع عملات المسير — جزء ERP-07

إجماليات PayrollRun الحالية مبالغ رقمية دون بُعد عملة أو سعر تحويل. لذلك يرفض المحرك عملات موظفين مختلفة قبل جمع الإجماليات وإرجاع المسير للحفظ. مقاطع راتب الموظف الواحد تتحقق أيضاً من العملة الناقصة، ورفض خليط العملات السابق يستعمل المقارنة نفسها.

التحقق يعامل trim/uppercase كاختلاف شكلي دون إعادة كتابة الهياكل أو سطور المسير القديمة. لا حد دولة أو ISO جديد ولا سعر صرف مفترض؛ اختيار كود ERP الصريح للراتب الجديد موثق في [EMP-12](HR_EMPLOYEE_SALARY_METADATA_2026-11-06_AR.md). هذه الحماية تتحقق من اتساق الأكواد، وليست إعادة اعتماد كتالوج العملات لكل سجل تاريخي.

عند الاعتماد يعاد التحقق من سطور المسير المخزنة قبل تسوية القروض أو تحديث حالة الاعتماد. المسير القديم بعملة ناقصة أو مختلفة يُرفض؛ مراجعة المصدر وإعادة الحساب هي المسار المطلوب، دون ملء عملة تاريخية تلقائياً. الدفعة ذات عملة واحدة تبقى مدعومة، والدفعة الفارغة تبقى مرفوضة بقواعد الاعتماد الموجودة.

## التحقق وحدوده

ثماني حالات جديدة تستعمل محرك الحساب وخدمة المسير وخدمة تحقق الاعتماد الفعلية مع مستودعات حساب/حفظ بديلة: الخليط/النقص لا يستدعي حفظ المسير، الاعتماد لا يستدعي تسوية القروض ولا يغير الحالة، وحساب عملة واحدة متطابقة شكلياً يعطي مجموعاً صحيحاً دون تعديل المصدر. نجحت مجموعة404 HR و160 عقد/فلتر/HTTP محدودة =564؛ سجل API المحدود erp07-currency-api-focused.log. التشغيل الأوسع دون المرشح توقف داخل QuestPDF.Skia بـAccessViolationException بعد98 حالة ولم يُحسب نجاحاً؛ تفاصيله erp07-currency-api.log. سجل erp07-currency-hr.log؛ ليس اختبار Oracle أو تزامن أو HTTP لسيناريو العملات.

## المتبقي

ERP-07 ما زالت مفتوحة: فصل ملفات ومجاميع العملات وربطها بعملة الحساب البنكي. `HrAccountingHandoffService` يتحقق في التحضير من أن وسيلة الدفع البنكية مرتبطة بحساب فعال في الفرع نفسه، وبعملة الحساب وGL المطابقين؛ تغطي `AccountingHandoffPaymentPreparationTests` حالات عدم النشاط والفرع/العملة/GL المخالف، والقبول المطابق (47 اختباراً في suite الملف). هذا يثبت مطابقة حساب دفعة واحدة فقط، ولا ينفذ تجميع أو تصدير ملفات متعددة العملات. تصدير `BankPayrollExportService` القديم مرفوض من متحكم الرواتب لأن الدفع مملوك لمسار Accounting؛ لذلك لا نعيد تفعيله كحل جانبي. يلزم Accounting أن يحدد شكل دفعة/ملف متعدد العملات وطريقة ربط كل مجموعة بالحساب البنكي قبل تنفيذ المسار. مطابقة عملة السطور بكود إعداد الترحيل/الفرع والتحقق من إجمالياتها أضيفتا لاحقاً ضمن [جزء ERP-04/05](HR_PAYROLL_POSTING_AUDIT_2026-11-06_AR.md)؛ إثبات Oracle والعكس والتزامن باقيان. لا تحويل عملات أو قبول بنك أو DDL أو نشر في هذه الحزمة.
