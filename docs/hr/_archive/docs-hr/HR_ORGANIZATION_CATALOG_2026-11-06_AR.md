# EMP-02 — إدارة كتالوج التنظيم

6 نوفمبر 2026. امتداد للتحقق من الإسناد ودورات المدير. يُعاد استخدام HR_DEPARTMENT وHR_POSITION الموجودين مع أعمدة التدقيق وHEADCOUNT/JOB_GRADE_CODE الفعلية، دون DDL. الاستبعاد من migrations يستمر لحماية الجداول القديمة.

## العقد

- GET /api/hr/organization/departments وpositions يعرضان الفعال بالنطاق؛ positions يقبل departmentCode.
- GET departments/{code} وpositions/{code} يعرض السجل المرئي حتى لو معطلاً، مع Version وETag.
- POST departments/{code} وpositions/{code} ينشئان رمزاً جديداً، ويرجعان 201 وETag ورابط القراءة.
- PUT departments/{code} وpositions/{code} يتطلب If-Match الحالي؛ النسخة القديمة 412، والناقص/غير الصحيح 400. لا upsert ولا حذف فعلي؛ IsActive الصريح للتعطيل وإعادة التفعيل.

القراءة hr-employees/view، والكتابة hr-employees/configure ضمن نظام الصلاحيات الحالي؛ لا self-service أو منح تلقائية. تعديل السجل المشترك بلا فرع يتطلب نطاق كل الفروع. الانتقال من سجل مشترك إلى فرع لا يتجاوز هذا الشرط. الفرع فعال ومن الشركة وفي نطاق الكاتب؛ المسمى يتبع نطاق إدارته القديمة والجديدة.

DepartmentWrite: NameLocal وNameEn مطلوبان حتى200، BranchId اختياري، ParentDepartmentCode اختياري، IsActive مطلوب صراحة في JSON. PositionWrite: DepartmentCode وعنوانان مطلوبان، ReportsToPositionCode اختياري، Headcount غير سالب وIsActive مطلوبان صراحة. الرموز حتى50، trim/uppercase. لا افتراض عدد موظفين أو تحويل Headcount لحد قانوني/حجز شاغر. JobGradeCode محجوب من JSON ولا يتيح الكتالوج قراءة درجة الأجر. CostCenterCode وJobGradeCode الموجودان يُحفظان دون تحريرهما أو اختلاق بديل عند الإنشاء؛ ربطهما المالي يحتاج عقد إعداد موثوق.

## الحماية

يُرفض الأب غير الفعال/غير المتاح، والتبعية لفرع مختلف، والدورات المباشرة وغير المباشرة والسلاسل المقطوعة. إعادة التسمية لا تنقل موظفاً أو تعيد حساب رواتبه. نقل/تعطيل إدارة مرتبطة بموظف أو مسمى أو إدارة فرعية أو سطر راتب تاريخي أو طلب توظيف مرفوض، وكذلك المسمى المرتبط بموظف أو مسمى تابع أو طلب توظيف. تشمل الحماية السجلات غير الفعالة وخارج نطاق الفرع دون إرجاع تفاصيلها.

الإنشاء يحفظ CreationUser/Date؛ التعديل يحفظهما ويحدّث UpdateUser/Date. بصمة النسخة تشمل الحقول والتدقيق، وتستعمل ticks للتوقيت حتى تتطابق قراءة Oracle غير المحددة النوع مع القيمة المتعقبة. يُفحص حد النص الفعلي في مخطط العميل قبل DML.

كتابة Oracle داخل ReadCommitted، بقفل فروع المخطط مرتبة حسب الشركة ثم المفتاح؛ يتداخل ذلك مع مراسي كتابة الموظفين الحالية لحماية التحقق من المراجع. هذه أقفال واسعة لعمليات الإعداد داخل مخطط العميل. تُرفض وحدة عمل ذات تغييرات معلقة؛ المعاملة المملوكة تتراجع وتنظف التعقب عند الفشل، والخارجية مسؤولية المستدعي. جلسات التزامن الفعلية ليست مثبتة بمجرد هذا التصميم.

## التحقق والمتبقي

الأدلة المحلية: emp02-catalog-api.log وemp02-catalog-hr.log. فحص Oracle وrollback: emp02-catalog-oracle.log؛ مقارنة الأصل بعده: emp02-catalog-preservation-after.log. نجح 363 اختبار HR و86 عقد/فلتر/HTTP=449، مع فحص Oracle وrollback وغياب مفاتيح الاختبار ثم مقارنة مستقلة59/59 جدولاً أصلياً.
