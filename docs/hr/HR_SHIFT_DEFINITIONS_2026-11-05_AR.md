# إدارة تعريفات الشفت — SHIFT-02

**التاريخ:** 5 نوفمبر 2026. أُنجزت API التعريفات والتحقق وحماية المراجع والتزامن. لم يتغير المخطط، ولم تُحفظ بيانات عمل تجريبية، ولم يُنشر التطبيق. متطلبات مخطط SHIFT-01 يجب أن تكون مطبقة قبل استعمال هذه الواجهات في مخطط آخر.

## العقد والصلاحيات

كل المسارات ضمن `api/hr/shifts` وتخضع للمصادقة وTenantScoped، دون قبول CompanyId يحدد العميل من جسم الطلب.

| الطريقة والمسار | الوظيفة | الصلاحية الحالية |
|---|---|---|
| GET /api/hr/shifts?activeOnly=false&search=...&page=1&size=50 | قائمة مرتبة بالكود، مع العدد الكلي وعلامة ارتباط التعريف | hr-attendance/view، دون خدمة ذاتية |
| GET /api/hr/shifts/{code} | تعريف وVersion، ويعيد ETag في الترويسة | hr-attendance/view |
| POST /api/hr/shifts | إنشاء تعريف جديد؛ الرد 201 مع Location وETag | hr-attendance/configure |
| PUT /api/hr/shifts/{code} | تعديل تعريف؛ يتطلب If-Match | hr-attendance/configure |
| DELETE /api/hr/shifts/{code} | حذف تعريف غير مرتبط؛ يتطلب If-Match | hr-attendance/configure |

لم تُضف أدوار أو منح صلاحيات إلى قاعدة البيانات. صلاحية تسجيل الحضور create وحدها لا تمنح configure. لا تُستعمل واجهة الكتالوج العامة كخدمة ذاتية؛ معاينة شفت الموظف في SHIFT-01 منفصلة.

مثال الإنشاء:

```json
{
  "shiftCode": "NIGHT_A",
  "definition": {
    "nameLocal": "شفت ليلي",
    "nameEn": "Night shift",
    "startTime": "22:00:00",
    "endTime": "06:00:00",
    "breakMinutes": 45,
    "workingDays": [0, 1, 2, 3, 4],
    "isActive": true
  }
}
```

PUT يستقبل محتوى `definition` نفسه دون تغيير الكود، مع `If-Match: "<Version من GET>"`. Version يظهر أيضاً في جسم الرد. يُرفض الطلب دون نسخة محددة؛ لا يدعم المفتاح `*` أو weak ETag. النسخة القديمة تعاد كـHTTP 412، ولا تُكتب فوق النسخة الأحدث.

## التحقق والسلوك

- البداية والنهاية والاستراحة والأيام وحالة التفعيل مطلوبة صراحة؛ لا افتراض لساعات أو أيام أو استراحة للشركة.
- أرقام الأسبوع 0=الأحد حتى 6=السبت. تُرفض التكرارات والقيم خارج المدى، وتُخزن الأيام بترتيب ثابت. القائمة الفارغة تعني عدم وجود أيام متكررة؛ اليومي الصريح يمكنه تحديد استثناء وفق SHIFT-01.
- أوقات البداية والنهاية clock times ضمن اليوم ومختلفة. نهاية أبكر من البداية تمثل ليلة تنتهي في اليوم التالي. الاستراحة غير سالبة وأقصر من مدة الشفت. التحقق مشترك مع خدمة الاختيار عبر ShiftDefinitionRules.
- الكود غير فارغ، حتى 50 حرفاً وفق عمود DEV_TEMPLATE الحالي، دون فواصل مسار أو محارف تحكم. الاسمان مطلوبان حتى 200 حرف لكل منهما؛ هذه حدود التخزين الحالية وليست قيود بلد أو لغة.
- القراءة تعرض WorkingDaysJson وValidationErrors إذا كان تعريف قديم معيباً؛ لا يُخترع له نمط أيام صالح. الكتابة الجديدة تحتاج تعريفاً صالحاً. لا يغير عرض الخطأ بيانات التعريف القديم.
- الصفحة حتى 100 صف، وpage حتى 1000000، ونص البحث حتى 200 حرف. تستخدم القائمة جلب مراجع مجمعاً بدلاً من استعلام لكل صف.

## حماية التاريخ والمراجع

IsInUse يعني وجود مرجع في أحد الجداول التشغيلية: HR_EMPLOYEE_SHIFT_ASSIGNMENT أو HR_EMPLOYEE_SHIFT_DAY أو HR_ATTENDANCE_DAY. يشمل المراجع المستقبلية والتاريخية وغير الفعالة، وليس إثبات دوام فعلي.

التعريف المرتبط يحتفظ بساعاته واستراحته وأيامه وحالة تفعيله؛ يمكن تغيير الاسم مع إبقاء الحساب نفسه، وترتيب أيام الأسبوع لا يعد تغييراً للحساب. التغيير التشغيلي يتم بإنشاء كود آخر ثم إسناده بالتاريخ الصحيح في SHIFT-03. الحذف والتعطيل مسموحان للتعريف غير المرتبط فقط. معالجة تعريف قديم معيب أو غير فعال لكنه مرتبط تحتاج مراجعة التوابع؛ لا يفرض هذا المسار إعادة تفسير الماضي.

فحص المراجع يتجاهل فلتر الموظف/الفرع لهذه الجداول داخل مخطط الشركة نفسه، ويعيد كوداً/علامة ارتباط فقط. لذلك لا يسمح ضيق نطاق المسؤول بتغيير تعريف مشترك استُخدم في فرع آخر، ولا يعرض له سجلات الموظفين الآخرين.

التعديل والحذف يمسكان صف التعريف بـFOR UPDATE داخل معاملة ReadCommitted، ثم يعيدان قراءة الصف ومقارنة النسخة وفحص المراجع قبل الكتابة. بعد الحفظ يُعاد تحميل metadata من Oracle حتى تطابق Version دقة TIMESTAMP الفعلية. يمنع القيد الأساسي تكرار الكود؛ خطأ التفرد في سباق الإنشاء يُحوّل إلى خطأ عملية دون اعتماد صف مكرر.

**اعتماديات الكتابة القادمة:** يجب أن تمسك واجهات الإسناد/اليومي والتوليد في SHIFT-03/04/05 صف الشفت نفسه قبل التحقق من التفعيل وحفظ المرجع، بترتيب أقفال متوافق. لا تثبت هذه الحزمة التزام تكاملات SQL القديمة بالبروتوكول، ولا تختبر جلستين متزامنتين. لا يوجد trigger جديد يمنع تحرير الكتالوج عبر SQL مباشر.
