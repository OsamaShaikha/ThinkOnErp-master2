# ATT-10 — إعداد موقع فرع الحضور المحفوظ

كشف اختبار HTTP أن SysBranch.Latitude/Longitude/GeofenceRadiusMeters/EnforceGeofence مستثناة من EF في إعداد ERP المشترك؛ البيانات التي كانت تظهر عند mock للفرع لا تبقى عند قراءة جديدة. لم يُغيّر هذا العمل تعيين SYS_BRANCH أو مستهلكي ERP الآخرين.

أضيف HR_BRANCH_ATTENDANCE_LOCATION: BranchId مفتاح/FK محدود الحذف إلى SYS_BRANCH، CompanyId، إحداثيان nullable، نصف قطر موجب، حالة تفعيل وتدقيق إنشاء/تعديل. AttendanceBranchRepository يقرأ الفرع المخوّل ويضيف إعداد الحضور المحفوظ إليه، للقرب والموبايل معاً. غياب الإعداد يبقى NO_BRANCH_COORDINATES وفق سياسة الشركة، ولا يُختار موقع أو تعطيل تلقائي. نصف قطر الفرع المهيأ يتقدم على الافتراضي العام؛ تعطيل الشركة أو الفرع صريح وraw يحتفظ بحالة عدم التحقق.

## API

المسار `api/hr/attendance/branches/{branchId}/location`؛ كل العمليات تحتاج hr-attendance/configure في الشركة والفرع. GET يعيد الإعداد أو null مع ETag عند وجوده. POST إنشاء أولي ويرجع 200؛ تكراره مع إعداد موجود 412 لإعادة القراءة. PUT يحتاج If-Match مع النسخة الحالية ويرجع 200؛ النسخة المتغيرة/النجمة لا تتجاوز الحماية وترجع 412. لا DELETE؛ تعطيل الرقابة إجراء صريح في الإعداد مع إبقاء الدليل السابق.

الجسم الكامل: latitude وlongitude وradiusMeters وenforceGeofence، كلها مفاتيح JSON مطلوبة صراحة. الإحداثيان يقبلان null معاً عند تعطيل الرقابة، ويلزمان عند تفعيلها؛ الصفر قيمة صحيحة. حدود الإحداثيات ±90 و±180، سبع منازل، ونصف القطر موجب حتى سعة NUMBER(10,2) بمنزلتين. لا تقريب صامت يغيّر حدود السماح، ولا حد موقع/مسافة قانوني موحد للشركات. hash النسخة يطبع decimal ويحترم ticks دون اختلاف DateTime.Kind عند Oracle.

المستودع يتحقق من النطاق ثم يقفل صف SYS_BRANCH داخل ReadCommitted ويعيد التحقق/تحميل الإعداد قبل مقارنة النسخة. يحفظ منشئ السجل، ويسجل المعدل والتوقيت. قبول raw السابق وإيصاله لا يعاد تقييمهما عند تغيير الموقع؛ أثر GPS السابق في الدليل ثابت ولا يعاد احتساب يوم مالي بسببه.
