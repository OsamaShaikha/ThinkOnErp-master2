# ATT-03 — تحديد حالة يوم الحضور

5 نوفمبر 2026. حساب مشترك لحالة اليوم يُستخدم في المحرك والموبايل والتصحيح، مع API معاينة وحفظ صريح. لا مهمة آلية تُنشئ غياباً لجميع الموظفين في هذه الحزمة، ولا نشر تطبيق.

المسار `api/hr/attendance/employees/{employeeCode}/day-classification?workDate=...`: GET بصلاحية hr-attendance/view وقراءة ذاتية ضمن النطاق، وPOST بصلاحية configure دون كتابة ذاتية. كلاهما يعيد اليوم المحسوب مع IsHoliday/HasApprovedLeave/HasOnlineEvidence/NeedsReview/ReviewReason. GET يحسب من الحالة الحالية دون حفظ؛ POST يعيد الحساب داخل قفل تاريخ الموظف/الرواتب ويحفظ الإنشاء أو التحديث ومستخدمه وتوقيته. لا accepts CompanyId أو Status جاهزة من العميل.

## قواعد التصنيف

| الدليل | النتيجة |
|---|---|
| دخول وخروج | PRESENT، بما فيه دليل الأونلاين |
| بصمة واحدة | INCOMPLETE مع إبقاء HasMissingPunch |
| بصمات مع إجازة معتمدة | REVIEW_REQUIRED؛ البصمات محفوظة ولا تُلغى الإجازة تلقائياً |
| دليل ONLINE معالج بلا بصمات يومية | REVIEW_REQUIRED لإعادة بناء اليوم؛ لا غياب صامت |
| لا بصمات مع عطلة فعالة للشركة/فرع الموظف | HOLIDAY |
| راحة صريحة أو لا شفت | REST_DAY أو UNSCHEDULED |
| إجازة يوم كامل معتمدة | ON_LEAVE مع رمز النوع |
| إجازة جزئية بلا أوقات، أو أكثر من إجازة معتمدة | REVIEW_REQUIRED؛ لا نفترض ساعات الجزء |
| شفت مطلوب لم ينته بعد بلا دليل | PENDING |
| شفت مطلوب انتهى بلا دليل أو استثناء | ABSENT |

استثناءات العطلة تشمل التاريخ المحدد والتكرار السنوي بالشهر/اليوم، وتحترم CompanyId وBranchId. عطلة فرع آخر لا تعفي الموظف. الراحة وعدم الجدولة لا تتحولان إلى غياب أو استهلاك إجازة بمجرد وجود طلب ضمن الفترة. هذه أولوية وصفية للحالة؛ تظهر أعلام الاستثناءات معاً، ولا تختار أجراً أو تسعيراً للعطلة أو الأونلاين.

ONLINE قيمة مصدر دليل فقط؛ لا تمنح تجاوزاً للموقع أو صلاحية إضافية. بصماته الصحيحة تُحسب مثل غيرها، وتبقى ضوابط الموبايل الجغرافية والصلاحيات الحالية نافذة. لا يثبت raw منفرد وحده دواماً كاملاً. قبول العمل عن بعد وإعداداته ضمن سياسة الشركة وصفحات SET-03؛ لا إذن عام جديد للعمل عن بعد في هذا API.

POST يرفض اليوم المستقبلي وفق منطقة العميل، ويرفض حفظ غياب PENDING قبل نهاية الشفت. اليوم القديم بلا لقطة توقيت يحتاج مراجعة صريحة؛ اختلاف لقطة الشفت يمنع الحفظ. لا مسح للدليل أو تبديل صامت بين تاريخين. الأعمدة الجديدة في حزمة التوقيت كافية؛ لم ينفذ DDL إضافي للتصنيف.

الحالة REVIEW_REQUIRED تمنع حساب المسير واعتماده عبر PayrollValidationService، مع فحص موظفي المسير والفترة. البصمة الحالية لمدخلات الرواتب تشمل AttendanceDay، لذلك تغير حالة يوم بعد الحساب يدخل مقارنة المدخلات القائمة. تبقى مراجعة كل الكُتّاب والسياسات وبوابات التزامن ضمن PAY-08/OPS-04. لا يُحوّل التصنيف الحالات إلى اقتطاع مالي مستقل ولا يدفع إضافياً تلقائياً.

## التحقق

نجح **242 اختباراً محدوداً**: حدود الغياب قبل/عند/بعد نهاية UTC، الراحة، عدم الجدولة، العطلة، الإجازة، التعارض والجزئي، الأونلاين، قفل الحفظ، ومنع حساب واعتماد مسير مع مراجعة معلّقة. نجح Oracle للحقائق والمعاينة وحفظ صف مراجعة اصطناعي: عطلة الشركة، استبعاد عطلة فرع آخر، إجازة/جزئي/تعارض، أونلاين كامل/دليل يتيم، غياب وراحة، استعلام بوابة الرواتب، وعزل ذاتي؛ تراجعت جميع البيانات وتحقق زوالها.

فحص Oracle لم يشغّل SaveAsync بمعاملته المالية الذاتية، ولا HTTP أو جلستين متزامنتين؛ فحص قفل POST محلي، وفحوص الحماية المالية الأخرى مستقلة. لا مزامنة عميل أو نشر. الأدلة المحلية: `artifacts/hr-audit/att03-suite.log` و`att03-oracle.log`، والأمر `--verify-attendance-status` في HrSchemaTool.
