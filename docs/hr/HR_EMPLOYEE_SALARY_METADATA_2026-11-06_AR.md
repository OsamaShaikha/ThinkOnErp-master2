# EMP-12 — عملة وطريقة دفع الراتب صريحتان

6 نوفمبر 2026. إزالة افتراض JOD/BANK_TRANSFER من إنشاء هياكل الرواتب عبر Excel، وتوحيد خطة المعاينة والحفظ والتحقق قبل تغيير الهيكل القديم. لا تعديل أعمدة أو تحويل بيانات قديمة أو اختيار إعداد شركة تلقائياً.

## عقد الملف

أضيف CurrencyCode وPaymentMethod في نهاية القالب/التصدير، بعد IsActive؛ مواقع الأعمدة القديمة لم تتغير. القارئ يقبل العناوين الإنجليزية/العربية ويطبّع trim/uppercase، ويترك الخلية المفقودة/الفارغة بلا افتراض. صف القالب إرشادي ويترك العملة/الدفع فارغين ليختار العميل قيمه.

أول هيكل راتب، سواء لموظف جديد أو موظف موجود بلا هيكل سابق واضح، يحتاج القيمتين صراحة. العملة تطابق ShortNameEn موحداً وفريداً في SYS_CURRENCY، كما تستعمله مخرجات المحاسبة الحالية؛ لا تُخمن من الاسم أو البلد أو أول عملة. تُرفض العملة غير المهيأة أو الملتبسة وحدود النص الفعلية في HR_SALARY_STRUCTURE قبل DML. الحد الاسمي20 حرفاً وليس افتراض ISO من3 أحرف؛ عمود العميل قد يكون أضيق، ولا يُوسع تلقائياً.

طرق الدفع المدعومة في عقد الراتب الحالي: BANK_TRANSFER وCASH وCHEQUE. اختيار CHEQUE لا يعني دعمها في ملف التحويل البنكي؛ شروط تصدير البنك ومواصفاته مستقلة. إدخال عملة/دفع دون BasicSalary مرفوض؛ البيانات لا تُتجاهل بصمت.

لراتب موجود، غياب العمودين يحافظ على بيانات الهيكل السابق عند إنشاء نسخة لاحقة. لا يتغير السجل القديم. التصريح بقيم مماثلة يؤكدها، والتصريح بقيم مختلفة يُرفض بـSALARY_METADATA_CHANGE_REQUIRES_ASSIGNMENT، حتى عند ثبات المبلغ أو تاريخ البداية؛ تغييرها يحتاج مسار إسناد الراتب المحمي. لا تحويل مبلغ أو إعادة تسمية عملة قديمة ضمن استيراد موظفين.

الأخطاء: SALARY_METADATA_REQUIRED للقيم الناقصة عند التهيئة، INVALID_SALARY_METADATA لكود/طريقة/تخزين غير صالح، وSALARY_REQUIRED للبيانات النقدية بلا مبلغ. الملف القديم بلا العمودين يظل قابلاً لتحديث راتب ذي بيانات سابقة؛ لا يهيّئ أول راتب بقيم مفترضة.

## المعاينة والحفظ

PreviewRows تضيف CurrencyCode وPaymentMethod المحسومتين عند خطة راتب صالحة، سواء نسخة جديدة أو مبلغ غير متغير؛ null عند عدم وجود خطة أو فشلها. التحقق من كتالوج ERP والتخزين مطلوب قبل إنشاء نسخة فعلية وقبل إغلاق السابقة؛ لا تُكتب نهاية السابقة إذا فشل التحقق. التكرار غير المنشئ لنسخة لا يعيد تصحيح الكتالوج التاريخي تلقائياً.

المعاينة استرشادية والحفظ يعيد فحوص المدخلات/المالية وصلاحيات EMP-04. إسناد الراتب المباشر أيضاً يطبّع ويتحقق من الكود/طريقة الدفع قبل تعديل الهياكل. تعريف العملة/الدفع لا يمنح صلاحية حقول الراتب ولا يغير قواعد CLOSED أو الاعتماد أو all-or-nothing للملف.

## التحقق

اختبارات XLSX حقيقي تحفظ القيم والدقة وثبات عمود IsActive، وتثبت توافق ملف قديم عند وجود سابق ورفض أول راتب ناقص. اختبارات الخدمة تغطي نقص/تغيير البيانات حتى عند ثبات المبلغ، الطرق الثلاث، وفشل الكتالوج قبل إغلاق السابق، واتساق المعاينة/الاستيراد/الإسناد. HTTP المحلي يقرأ ملفاً حقيقياً ويهيئ معاينة USD/CASH من كتالوج تجريبي وبحقوق الحقول الست، ويمنع الفرع غير المخول؛ توجيه العميل وInMemory ليسا Oracle HTTP.

--verify-salary-metadata يختبر SQL الكتالوج وحدود الأعمدة على Oracle، ويرفض عملة مجهولة وطريقة غير مدعومة. صف راتب غير فعال داخل transaction يثبت تخزين العملة الصريحة/CASH ودقة3 منازل، ثم rollback وغياب الصف وثبات العملات/الدفع/نهايات الهياكل الأصلية. ليس استيراداً ناجحاً بمعاملة مملوكة أو حساب FX أو قبول بنك. الأدلة emp12-salary-metadata-*.log ومقارنة مستقلة59 جدولاً أصلياً بعد fixtures.

## حدود العملات المتعددة

هذا تهيئة بيانات الراتب، وليس إعداد تحويل عملات أو مجموعات دفع متعددة. PayrollSalarySegments يرفض اختلاف عملات مقاطع الموظف الواحد. أضيف لاحقاً رفض تجميع/اعتماد العملات المختلطة أو الناقصة بين موظفين مختلفين ضمن جزء ERP-07؛ [العقد](HR_PAYROLL_CURRENCY_GUARDS_2026-11-06_AR.md). بقي فصل دفعات العملات ضمن ERP-07؛ أُضيفت مطابقة عملة سطور المسير بعملة القيد في [جزء ERP-04/05](HR_PAYROLL_POSTING_AUDIT_2026-11-06_AR.md)، وإثبات الترحيل/العكس ما زال مفتوحاً، مع مواصفات البنك ERP-06 ولقطات قديمة ERP-09. لا اختيار سعر صرف أو حساب شركة، ولا ادعاء إزالة كل fallback تاريخي في محرك الرواتب أو بقية ERP.
