# ATT-01 — هوية أحداث الحضور وإعادة المحاولة

5 نوفمبر 2026. أضيف منع التكرار لعقد بصمة الموبايل واستقبال دليل الأجهزة، مع تحقق Oracle. لم يُنشر التطبيق أو يُحدّث عميل موبايل خارج المستودع.

## الموبايل

POST check-in/check-out الحالي يحتاج `eventId` UUID غير فارغ، بصيغة D أو N. يولّد العميل المعرّف مرة واحدة للبصمة ويحفظه لإعادة المحاولة؛ لا ينشئ UUID جديداً مع كل محاولة شبكة. الحقل مطلوب في تحقق API وفي الخدمة، مع بقاء معامل C# الافتراضي للتوافق المصدري فقط. العملاء السابقون يحتاجون إضافة الحقل قبل نشر هذا العقد.

يُحفظ مع raw المعرّف وبصمة المحتوى وJSON لنتيجة القبول الأصلية، في معاملة استقبال دليل مستقلة عن تحديث اليوم، وفق عقد ATT-07 ذي إيصال 202. المحتوى يشمل الموظف ونوع البصمة والموقع والفرع والدقة والجهاز والمصدر. تكرار نفس الحدث يعيد **النتيجة الأصلية بما فيها وقت القبول** دون تحديث اليوم أو raw، حتى بعد إقفال الفترة. تغيير تفاصيل حدث مقبول بنفس المعرّف يرجع 409. الأرقام ذات المنازل الصفرية المكافئة وصيغ UUID المكافئة تُطبّع ولا تسبب تعارضاً وهمياً.

القراءة المتكررة تظل بحاجة لصلاحية create الحالية ونطاق الموظف الحالي؛ لا يتجاوز المفتاح المصادقة أو العزل. يُبحث قبل الأقفال وبعد قفل الموظف داخل معاملة الدليل؛ فهرس Oracle حارس إضافي. الرفض الجغرافي يحفظ الآن raw نهائياً REJECTED مع سبب وإيصال 400 قابل لإعادة المحاولة؛ كان وصف ATT-01 الأولي يقصر ذلك على المقبول. [العقد الجاري ATT-07](HR_MOBILE_EVIDENCE_2026-11-05_AR.md).

## الأجهزة

IngestPunchAsync يحتاج deviceId وsource وeventId ثابتاً من المصدر، ووقت UTC صريحاً ونوع IN/OUT. معرّف المصدر يمكن أن يكون عداداً/نصاً حتى 200 محرف؛ يجب على المحول تضمين نطاق جلسة الجهاز إذا كان عداده يعاد من الصفر. المفتاح الداخلي D: مع SHA-256 لهوية المصدر/الجهاز/حدثه؛ الموظف ضمن القيد الفريد. تغيير وقت الحدث المقبول أو نوعه يُرفض، ونفس معرّف المصدر على جهاز آخر حدث مستقل. لا يعتمد منع التكرار على تقريب الوقت إلى الثانية.

المستودع يتحقق من الموظف والشركة/الفرع، ويقفل الموظف داخل ReadCommitted، ثم يعيد raw الأصلي أو يحفظ واحداً فقط. استقبال الدليل لا يقفل فترة الرواتب ولا يعدّل AttendanceDay، ويُبقي IsProcessed=false؛ لذلك يُحفظ حتى عند CLOSED. معالجة raw إلى اليوم المالي مشتركة مع ATT-06، وحفظ دليل الموبايل عند رفض الكتابة المالية مكتمل في ATT-07. لا يدّعي هذا التغيير وجود API أجهزة جديد أو عامل معالجة منشور.

## المخطط والنسخة

أضاف `--install-mobile-punch-events` ثلاثة أعمدة nullable على HR_RAW_ATTENDANCE: EVENT_ID وEVENT_PAYLOAD_HASH وEVENT_RESPONSE_JSON من نوع NCLOB للنتيجة. الفهرس الوظيفي UX_HR_MOBILE_EVENT يحمي الموظف/الحدث؛ صفوف EventId NULL القديمة مستبعدة منه فلا تُعاد كتابة الأدلة أو حذف المتكرر القديم. الاسم تاريخي ويغطي حالياً أسماء الموبايل والأجهزة.

أثناء توسيع مساحة المفتاح إلى 100 محرف، احتاج Oracle إعادة إنشاء الفهرس الوظيفي حول توسعة العمود. الأداة ترفض هذه الترقية إذا وُجد أي حدث مقبول؛ تحقق التطبيق الحالي من صفر أحداث، وأعاد إنشاء الفهرس على DEV_TEMPLATE فقط، قبل أي نشر للتطبيق. عند وجود بيانات مقبولة يلزم انتقال معزول مستقل. [تفسير Oracle لـORA-30556](https://docs.oracle.com/en/error-help/db/ora-30556/).

نسخة محلية قبل هذه الحزمة: `artifacts/hr-audit/backups/20261105154142/dev_template_20261105154142.dmp`، 8,519,680 بايت، SHA-256 `33BC15DCE39F37B77344CCFCF52B67110598081777B739A57AFB44C48DB6B330`، COMPLETED. تمرين الاستعادة OPS-11 ما زال منفصلاً. لم تُمنح صلاحيات أو تُزامن مخططات عملاء.

## التحقق

نجح بناء API و**262 اختباراً محدوداً**. الحالات الجديدة تشمل المفتاح المفقود، الهوية/المحتوى، النتيجة الأصلية دون كتابة أو إعداد توقيت، العزل، قبولاً تزامن مع انتظار قفل مالي، وأحداث الجهاز وUTC ودقة الوقت واختلاف الأجهزة.

نجح `--verify-mobile-punch-events` على Oracle داخل rollback: OUT موبايل ليلي فعلي، نفس النتيجة بعد إقفال اصطناعي، رفض محتوى متغير، raw واحد، منع تكرار SQL، قبول صفين legacy NULL، ثم استقبال دليل جهاز أثناء CLOSED وإعادة نفس raw ورفض الوقت المتغير وفصل جهازين دون إنشاء يوم مالي. تراجعت كل البيانات وتحقق زوالها. تطابقت الأعمدة والبيانات الأصلية في 59/59 جدولاً؛ 40 نوع EF مقابل 65 جدول HR.

لم تُختبر جلستان متزامنتان فعلياً أو HTTP/موبايل حقيقي، ولم يُنشر التطبيق. الاختبار الذي يحاكي انتظار القفل محلي وليس إثبات تزامن Oracle. الأدلة في `artifacts/hr-audit/att01-suite.log` و`att01-schema.log` و`att01-oracle.log` و`att01-build.log` و`att01-preservation.log`.
