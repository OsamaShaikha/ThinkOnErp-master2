# SHIFT-04 — API جدول الموظف اليومي

5 نوفمبر 2026. أُضيف CRUD اليومي في الكود، مع تحقق Oracle على DEV_TEMPLATE. يستخدم جدول SHIFT-01 الموجود؛ لا تغيير مخطط أو منح صلاحيات أو نشر أو مزامنة عميل.

## المسارات والصلاحيات

المسار الأساسي: `api/hr/employees/{employeeCode}/shift-days`.

| العملية | المسار | الصلاحية والنتيجة |
|---|---|---|
| قائمة | GET | hr-attendance/view، قراءة ذاتية ضمن نطاق الموظف؛ 200 |
| تفاصيل | GET /{id} | نفس القراءة؛ 200 مع ETag |
| إنشاء | POST | hr-attendance/configure؛ 201 مع Location وETag |
| تعديل/تفعيل/تعطيل | PUT /{id} | configure، If-Match لنسخة اليوم؛ 200 مع ETag |
| حذف | DELETE /{id} | configure، If-Match؛ 200 |

القائمة تدعم from/to شاملين وactiveOnly وpage/size؛ الحجم 1–100. يعرض السجل مصدره، ونسخته، ونسخة/حالة التعريف الحالية، والمستخدم والتوقيت UTC للإنشاء والتعديل. رمز الموظف من المسار؛ لا يُقبل تحديد شركة أو موظف بديل في الجسم. القراءة تخضع لنطاق الموظف/الفرع والمخطط الحالي، والكتابة ليست ذاتية.

مثال يوم عمل:

```json
{
  "workDate": "2026-12-01",
  "shiftCode": "SHIFT_A",
  "isRestDay": false,
  "isActive": true,
  "shiftVersion": "<current version from shift catalog>"
}
```

مثال راحة:

```json
{
  "workDate": "2026-12-02",
  "shiftCode": null,
  "isRestDay": true,
  "isActive": true,
  "shiftVersion": null
}
```

WorkDate وIsRestDay وIsActive مطلوبة صراحة. يوم الراحة لا يقبل رمز شفت أو نسخته؛ يوم العمل يحتاج كليهما. If-Match في PUT/DELETE هو نسخة السجل اليومي، وshiftVersion في POST/PUT نسخة تعريف الشفت. تُرفض النسخة القديمة بـ412. الحقول الإضافية مثل source لا تُستخدم لتغيير المصدر؛ الخادم يكتب MANUAL دائماً.

## السلوك والحماية

- سجل واحد لكل موظف/تاريخ محلي حتى لو كان غير فعال. يرفض الإنشاء المكرر أو النقل إلى يوم مشغول؛ يُعدّل السجل الموجود لإعادة تفعيله. يبقى القيد الفريد في Oracle حارساً إضافياً.
- اليوم الفعال يتقدم على الإسناد المؤقت والأساسي؛ الراحة الفعالة تمنع اختيار شفت من الإسناد. اليوم غير الفعال يتيح الرجوع إلى الإسناد. الشفت اليومي استثناء صريح من نمط أيام الأسبوع، وفق SHIFT-01؛ لا تُفرض أيام دوام موحدة.
- تعديل يوم GENERATED يدويّاً يحوّله إلى MANUAL، ويحفظ منشئه الأصلي مع مستخدم/توقيت التعديل. لا يوجد endpoint لتوليد أيام أو اختيار GENERATED من العميل؛ التوليد في SHIFT-05 مع حماية التعديلات اليدوية.
- كل كتابة بما فيها الراحة والسجل غير الفعال والحذف تفحص يومها؛ النقل يفحص التاريخين القديم والجديد. تُمنع الكتابة على حضور محفوظ أو فترة CLOSED أو مسير APPROVED/POSTED_TO_GL/PAID يضم الموظف. حتى إعادة الحفظ دون تغيير حسابي تبقى محمية؛ لا إعادة احتساب حضور صامتة.
- الأقفال داخل ReadCommitted: الفترات ثم الموظف ثم صف اليوم عند التعديل/الحذف ثم رموز التعريف مرتبة. مشاركة قفل التعريف مع SHIFT-02 تمنع سباق إدخال مرجع مع حذف/تغيير تعريف غير مستخدم. تُعاد قراءة نسخة اليوم والتعريف بعد القفل.
- كل مرجع جديد يحتاج تعريفاً فعالاً ولو كان اليوم غير فعال؛ اليوم الفعال يحتاج تعريفاً صالحاً للساعات والأيام. المرجع القديم غير الفعال يمكن إبقاؤه عند تعطيل اليوم، أو تغييره إلى راحة. حذف مرجع يتيم مسموح فقط مع اجتياز حماية التوابع.
- الحذف فعلي مثل بقية APIs الحالية؛ حقول الإنشاء/التعديل تدقيق للسجلات الباقية، وليست دفتر تاريخ غير قابل للحذف. لا تضيف الحزمة سير عكس حضور أو اعتماد رواتب.

## أدلة التحقق والحدود

- بناء API والأداة ناجح بصفر أخطاء مع تحذيرات المشروع الحالية.
- **172 اختباراً ناجحاً** في مجموعة HR المحدودة، منها 17 حالة جديدة للتحقق، نطاق القراءة، تحويل التعديل إلى MANUAL، وتغيّر النسخة عند تغيير عناصر الجدول. ليست مجموعة المستودع الكاملة.
- فحص Oracle `--verify-shift-days`: CRUD والراحة والتفعيل والنقل، منع تكرار غير الفعال، أثر تعديل GENERATED على المصدر والتدقيق، نسخ اليوم/التعريف القديمة، تعريف غير فعال، حضور في التاريخ القديم والجديد، فترة مقفلة ومسير معتمد، قائمة الفعال والقراءة الذاتية؛ **14 حالة رفض متوقعة**.
- الفحص أدخل بيانات اصطناعية في سنة 9019 داخل معاملة متراجع عنها، ثم تحقق من زوال الأيام والتعريفات والحضور وفترة/مسير الاختبار. تغيّر حالة المسير يخص بيانات الاختبار فقط. قد تستهلك identity أرقاماً دون صفوف باقية.
- مقارنة الأعمدة والبيانات الأصلية مع baseline: **59/59** بعد rollback. الجدول اليومي سبق تركيبه في SHIFT-01؛ لم ينفذ DDL هنا.
- لم تُنفّذ اختبارات جلستين متزامنتين أو HTTP/تفويض فعلي، ولا نشر التطبيق أو مزامنة عميل، ولا شاشة ويب. ربط الحضور ATT-02 والتوقيت الكامل SHIFT-06 والتوليد SHIFT-05 تبقى مهام مستقلة.
