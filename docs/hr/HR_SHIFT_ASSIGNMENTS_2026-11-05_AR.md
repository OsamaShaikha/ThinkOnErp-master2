# SHIFT-03 — إسناد الشفت الأساسي والمؤقت

التاريخ: 5 نوفمبر 2026. التنفيذ في الكود وفحص DEV_TEMPLATE؛ لا نشر تطبيق أو مزامنة عملاء، ولا تعديل مخطط أو منح صلاحيات في هذه الحزمة.

## عقد API

المسار: `api/hr/employees/{employeeCode}/shift-assignments`.

| العملية | الطلب | الصلاحية والنتيجة |
|---|---|---|
| القائمة | GET مع from/to وactiveOnly وpage/size | hr-attendance/view؛ قراءة ذاتية ضمن نطاق الموظف؛ 200 |
| التفاصيل | GET /{id} | نفس صلاحية القراءة؛ 200 مع ETag |
| الإنشاء | POST | hr-attendance/configure؛ 201 مع Location وETag |
| التعديل | PUT /{id} | configure مع If-Match لنسخة الإسناد؛ 200 مع ETag |
| الحذف | DELETE /{id} | configure مع If-Match؛ 200 |

جسم الإنشاء والتعديل:

```json
{
  "shiftCode": "SHIFT_A",
  "assignmentKind": "TEMPORARY",
  "effectiveFrom": "2026-12-01",
  "effectiveTo": "2026-12-15",
  "isActive": true,
  "shiftVersion": "<version from shift catalog>"
}
```

تاريخ البداية والتفعيل مطلوبان صراحة. النوع BASE أو TEMPORARY؛ المؤقت يحتاج نهاية، والأساسي يمكن أن يكون محدداً بنهاية. الموظف من المسار، ولا يقبل الجسم شركة أو موظفاً بديلاً. حدود الفترة شاملة للطرفين. حجم الصفحة 1–100. نسخة الإسناد ونسخة التعريف منفصلتان؛ النسخة القديمة ترد 412، ولا يقبل If-Match العام أو الضعيف. نسخة التعريف الحالية مطلوبة في POST/PUT.

## قواعد الحفظ والحماية

- المؤقت يتقدم على الأساسي وفق خدمة SHIFT-01. يرفض تداخل مؤقتين فعالين حتى لو اتفق رمز الشفت، ويسمح بتجاور فترتين دون اشتراك يوم. الأساسي المتداخل مسموح فقط عند عدم اشتراك أيام عمل فعلية ضمن تقاطع الفترتين، مثل أيام الأسبوع وعطلة الأسبوع المكملة.
- يرفض التكرار المطابق في الشفت والنوع الفعلي والتفعيل والفترة، بما فيه السجل غير الفعال. هذا فحص تكرار، وليس دفتر مفاتيح طلبات idempotency دائم.
- المرجع الجديد يحتاج تعريفاً فعالاً حتى لو كان الإسناد المقترح غير فعال. يمكن تعطيل إسناد قديم مرتبط بتعريف غير فعال إذا لم تمنع التوابع ذلك. حذف المرجع اليتيم يظل خاضعاً لحماية التوابع.
- عند تغيير الشفت أو النوع الفعلي أو التفعيل، تُحمى الفترتان القديمة والجديدة. عند تعديل الحدود فقط، تُفحص التواريخ المضافة والمحذوفة دون الجزء المشترك؛ لذلك يمكن إنهاء إسناد مستقبلاً مع بقاء حضور تاريخي غير متغير.
- يمنع المساس بالتواريخ المتأثرة داخل فترة رواتب CLOSED أو مسير APPROVED/POSTED/PAID يضم الموظف، وكذلك أيام الحضور المحفوظة والجدول اليومي الفعال. الجدول غير الفعال لا يمنع تعديل الإسناد الذي سيعمل كخيار بديل. فحص التوابع بحسب الموظف/التاريخ محافظ لأن اليوم لا يحفظ SourceAssignmentId.
- معاملة ReadCommitted وأقفال بالترتيب: الفترات ثم الموظف ثم الإسناد عند تعديله/حذفه ثم رموز التعريف مرتبة. تُعاد قراءة النسخ والتفعيل بعد الأقفال. قفل التعريف مشترك مع كتالوج SHIFT-02. يرفض الانضمام إلى معاملة بعزل آخر تجنباً لقراءة لقطة قديمة بعد انتظار القفل.
- استُخرج قفل الموظف/الرواتب إلى HrEmployeePayrollLock وأعيد استخدامه في HrUnitOfWork الحالي؛ يشمل المسيرات التاريخية المخفية بنطاق الفرع، ويرفض تغيّر فرع الموظف أثناء اكتساب الأقفال.

## الإسنادات القديمة

القراءة تعرض AssignmentKind الأصلي وEffectiveKind وIsLegacy. توافق NULL القديم كما في SHIFT-01: المفتوح أساسي والمحدود مؤقت؛ لا تعيد هذه الحزمة تصنيف البيانات تلقائياً. كتابة API الجديدة صريحة. الانتقال من NULL إلى النوع المكافئ لا يغيّر أياماً؛ أما إعادة تفسير سجل محدود من مؤقت إلى أساسي فتُفحص فترته كاملة وتمنعها التوابع المحمية.

فحص DEV_TEMPLATE: **5 إسنادات NULL مفتوحة، وصفر NULL محدود**. لم تتغير أنواعها أو قيمها الدائمة. قبل مزامنة عميل آخر ضمن OPS-03، يجب تدقيق NULL المحدود وتحديد معناه التاريخي؛ لا نفترض أن الأساسي الذي أُغلق عند الاستبدال كان مؤقتاً.

## التحقق وحدوده

- نجح بناء API: صفر أخطاء؛ توجد تحذيرات البناء الحالية.
- نجح 155 اختبار HR في المجموعة المحدودة، منها 25 حالة جديدة للفترات والتحقق والنطاق؛ ليست مجموعة المستودع الكاملة.
- نجح `--verify-shift-assignments` على Oracle بمعاملة متراجع عنها: CRUD، تعارضات وتجاور، أساسيان بأيام مكملة، تعديل المستقبل مع حضور سابق، حضور/يومي فعال، نسخ قديمة، تعريف غير فعال، فترة مقفلة ومسير معتمد، تصنيف قديم مكافئ، وقراءة ذاتية خارج النطاق. شمل 11 حالة رفض متوقعة.
- أعيدت أعلام الإسنادات الأصلية وقورنت معرفاتها بعد rollback؛ لم تبق تعريفات أو إسنادات أو أيام أو حضور أو رواتب اختبارية. أرقام identity المستهلكة قد تترك فجوات. حالات الرواتب الاصطناعية في الفحص ليست تنفيذ سير عكس اعتماد مالي.
- تطابقت بيانات وأعمدة الجداول الأصلية **59/59** مع baseline. المخطط الحالي راجع 39 نوع EF مقابل 64 جدول HR.
- لم تُجرّب جلستان متزامنتان أو HTTP فعلي/تفويضه، ولم يكتمل ربط محرك الحضور أو التوقيت الكامل. API الجدول اليومي التالي SHIFT-04، والتوليد SHIFT-05.
