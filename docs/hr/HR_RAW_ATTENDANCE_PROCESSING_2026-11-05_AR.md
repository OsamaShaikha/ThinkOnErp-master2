# ATT-06 — استقبال ومعالجة دليل الأجهزة

5 نوفمبر 2026. استقبال موثوق مع إعادة محاولة آمنة، وطابور معالجة صريح، وربط الدليل بتاريخ العمل ويوم الحضور. لا عامل background منشور أو مزامنة عميل أو نشر تطبيق.

## API

جميع عمليات الإدخال والمعالجة والتجاهل تحتاج hr-attendance/configure، دون صلاحية ذاتية. المصدر هو تكامل موثوق أو موظف HR مخوّل؛ ليس مساراً للموبايل لتجاوز GPS.

| الطلب | المسار تحت api/hr/attendance/raw-events | الغرض |
|---|---|---|
| POST | الجذر | employeeCode، occurredAt بصيغة Z/offset، punchType IN/OUT، deviceId، eventId ثابت من المصدر، source |
| GET | /{id}?employeeCode=... | view وقراءة ذاتية ضمن النطاق؛ لا يرجع سجل موظف مختلف عن المعطى |
| GET | /pending?size=100 | أول 1–100 حدث غير معالج، مرتبة بالوقت ثم المعرف |
| POST | /{id}/process | تطبيق حدث واحد أو إعادة نتيجته النهائية دون كتابة أخرى |
| POST | /process-batch | جسم `{ "size": 100 }`؛ نتيجة مستقلة لكل صف دون إسقاط الفشل |
| POST | /{id}/ignore | جسم `{ "reason": "..." }`؛ تجاهل مسبب للدليل غير المطبق فقط |

الردود لا تعرض بصمة المحتوى أو JSON نتيجة الموبايل الداخلية. تعرض هوية المصدر والحدث، UTC، تاريخ العمل، رابط اليوم، النتيجة والمراجع وتوقيت القرار، وآخر محاولة معالجة وسبب تعذّرها. الحد تشغيلي للطلب، وليس قاعدة دوام للشركات.

## المعالجة والحماية

يستعمل الموبايل والمعالج AttendanceWorkDateResolver نفسه: تاريخ العميل الحالي والسابق، أولوية اليوم المفتوح عند OUT، نافذة الشفت ثم تاريخ العميل الحالي عند عدم المطابقة. الدليل القديم بلا هوية مصدر/UTC يحتاج مراجعة؛ لا يخمن المعالج توقيته. المستقبل ونوع حدث غير معروف مرفوضان من المعالجة المالية مع إبقاء الدليل.

أولاً يربط الدليل بتاريخ مرشح داخل معاملة دليل بقفل الموظف/صف raw؛ لا يغيّر يوماً مالياً. لا يعاد نقل ربط سابق إلى تاريخ مختلف بصمت. بعدها معاملة ReadCommitted مالية بأقفال الفترات ثم الموظف ثم raw، وإعادة قراءة الدليل والتاريخ قبل الحساب. الحارس المشترك يمنع CLOSED والمسير المعتمد. تحفظ النتيجة ورابط اليوم والتصنيف معاً؛ الفشل المالي يترك raw معلقاً ولا ينشئ نصف يوم. يمكن للمستودع الانضمام إلى معاملة ReadCommitted خارجية؛ مالكها مسؤول عن rollback، ولا يسمح بعزل آخر.

تُجمع أول IN وآخر OUT مع الدليل المطبق والقيم المعروفة لليوم، وتُحسب جلسة واحدة بمحرك ATT-02. وجود جلسات متعددة أو نوعين متعاكسين في اللحظة نفسها أو ترتيب معكوس يوقف التطبيق للمراجعة؛ لا نفترض مدة فجوات العمل أو نطرح الاستراحة مرتين. احتساب الجلسات المتعددة وسياسة الفجوات والاستراحات ضمن ATT-09. لا يسمح المعالج بكتابة raw متأخر فوق يوم ذي تصحيح معتمد؛ يُراجع الدليل أو يُتجاهل بسبب موثق. الدليل الأسبق لنفس تاريخ العمل يراجع قبل الأحدث، وبحد حجم يمنع تجاهل backlog كبير بصمت.

تُرفض الكتابة المالية خارج تاريخ التعيين/الإنهاء، مع بقاء الدليل الخام للمراجعة. هذا تحقق لعلاقة الموظف باليوم، وليس فرض سياسة بلد. وضع IsActive الحالي لا يمحو حق معالجة تاريخ قديم داخل فترة التوظيف.

التجاهل يغيّر نتيجة الدليل فقط إلى IGNORED مع السبب والمراجع وUTC، ولا يحذف الدليل ولا يعدّل اليوم أو يفك دليلاً مطبقاً. تكرار نفس قرار التجاهل يعيد التدقيق الأصلي. تجاهل دليل معلق لا يزيل حالة مراجعة مالية محفوظة تلقائياً؛ بعد مراجعة الطابور يمكن استعمال POST تصنيف اليوم تحت قفله المالي.

حالات المراجعة وraw الجديد غير المعالج تمنع حساب واعتماد المسير في الفترة المعنية. إذا لم يربط raw بعد، يحدد حارس الرواتب تاريخه للقراءة فقط عبر نفس resolver والمنطقة؛ ما تعذر تفسيره داخل حدود الفترة يحتاج مراجعة. الأدلة القديمة بلا EventId لا تتحول تلقائياً إلى النموذج الجديد، ومراجعتها قبل الإطلاق ضمن OPS-03. الأونلاين المتجاهل أو المرفوض لا يتحول إلى حضور معتمد.
