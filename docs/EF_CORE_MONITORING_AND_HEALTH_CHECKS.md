# EF Core Monitoring and Health Checks

## Overview

This document describes the monitoring and health check capabilities implemented for Entity Framework Core (EF Core) in the ThinkOnErp ERP system. These features implement **REQ-21: Monitoring and Observability** from the EF Core migration specification.

## Features Implemented

### 1. SQL Query Logging with Execution Times

All SQL queries generated by EF Core are logged with their execution times through the `EfCorePerformanceInterceptor`.

**Configuration** (`appsettings.json`):
```json
{
  "EfCore": {
    "Logging": {
      "Enabled": true,
      "LogSqlQueries": true,
      "LogQueryExecutionTime": true,
      "SlowQueryThresholdMs": 1000,
      "LogConnectionEvents": true
    }
  }
}
```

**Features:**
- Logs all SQL queries at Debug level
- Logs query execution times at Information level
- Flags slow queries (>1000ms by default) at Warning level
- Automatically logs slow queries to `SYS_SLOW_QUERY` table for analysis
- Includes query parameters (sanitized for security)
- Tracks query execution duration in milliseconds

**Log Output Example:**
```
[2024-01-15 10:30:45.123] [INF] EF Core query executed in 245ms. CommandId: abc123
[2024-01-15 10:31:12.456] [WRN] Slow EF Core query detected (1523ms). CommandId: def456, SQL: SELECT * FROM SYS_COMPANY WHERE...
```

### 2. Connection Pool Monitoring

The `EfCoreConnectionPoolMonitor` service provides real-time metrics about the Oracle connection pool used by EF Core.

**Metrics Available:**
- Min/Max pool size configuration
- Current pool utilization (estimated)
- Connection timeout settings
- Connection lifetime configuration
- Pooling enabled status
- Database connectivity status

**API Endpoint:**
```
GET /api/monitoring/efcore/connection-pool
Authorization: Bearer {token}
```

**Response Example:**
```json
{
  "poolMetrics": {
    "isAvailable": true,
    "minPoolSize": 5,
    "maxPoolSize": 100,
    "connectionTimeout": 15,
    "connectionLifetime": 300,
    "poolingEnabled": true,
    "canConnect": true,
    "timestamp": "2024-01-15T10:30:00Z"
  },
  "diagnostics": {
    "connectionType": "OracleConnection",
    "connectionState": "Closed",
    "database": "XEPDB1",
    "dataSource": "178.104.126.99:1521/XEPDB1",
    "serverVersion": "Oracle Database 21c Express Edition",
    "canConnect": true,
    "connectionTestDurationMs": 45,
    "queryTestDurationMs": 12
  },
  "health": {
    "isHealthy": true,
    "status": "Healthy",
    "message": "EF Core DbContext connection pool is healthy"
  }
}
```

### 3. Health Check Endpoints

Three health check endpoints are available for monitoring EF Core DbContext connectivity:

#### a. Basic Health Check
```
GET /health
```

Returns comprehensive health status for all system components including EF Core DbContext.

**Response Example:**
```json
{
  "status": "Healthy",
  "timestamp": "2024-01-15T10:30:00Z",
  "duration": 125.5,
  "checks": [
    {
      "name": "efcore_dbcontext",
      "status": "Healthy",
      "description": "EF Core DbContext is healthy",
      "duration": 45.2,
      "data": {
        "queryExecutionTimeMs": 12.3,
        "connectionState": "Closed",
        "database": "XEPDB1",
        "totalCheckDurationMs": 45.2,
        "timestamp": "2024-01-15T10:30:00Z"
      }
    }
  ]
}
```

#### b. Readiness Check
```
GET /health/ready
```

Returns readiness status (checks if app is ready to serve traffic). Includes EF Core DbContext check.

**Response Example:**
```json
{
  "status": "Healthy",
  "timestamp": "2024-01-15T10:30:00Z"
}
```

#### c. Liveness Check
```
GET /health/live
```

Returns liveness status (checks if app is alive). Always returns 200 OK if the application is running.

#### d. EF Core Specific Health Check
```
GET /api/monitoring/efcore/health
```

Returns detailed EF Core DbContext health information.

**Response Example:**
```json
{
  "status": "Healthy",
  "canConnect": true,
  "connectionTestDurationMs": 45,
  "queryTestDurationMs": 12,
  "database": "XEPDB1",
  "dataSource": "178.104.126.99:1521/XEPDB1",
  "timestamp": "2024-01-15T10:30:00Z",
  "message": "EF Core DbContext is healthy and can connect to database"
}
```

### 4. Integration with Serilog

All EF Core monitoring logs are integrated with the existing Serilog infrastructure:

**Log Enrichment:**
- Correlation ID for request tracing
- Machine name for distributed deployments
- Thread ID for concurrency analysis
- Timestamp with timezone

**Log Destinations:**
- Console output (development)
- Rolling file logs (`logs/log-YYYYMMDD.txt`)
- Structured JSON format for log aggregation

**Log Levels:**
- Debug: SQL query text
- Information: Query execution times
- Warning: Slow queries (>1000ms)
- Error: Query failures and connection issues

### 5. Slow Query Detection and Alerting

Slow queries are automatically detected and logged to the database for analysis.

**Threshold Configuration:**
```json
{
  "EfCore": {
    "Logging": {
      "SlowQueryThresholdMs": 1000
    }
  }
}
```

**Alert Configuration:**
```json
{
  "Alerting": {
    "AlertRules": {
      "SlowQueryDetected": {
        "Enabled": true,
        "Severity": "Medium",
        "Channels": ["Email"]
      }
    }
  }
}
```

**Slow Query Repository:**
Slow queries are stored in `SYS_SLOW_QUERY` table with:
- Query text (truncated to 4000 characters)
- Execution time in milliseconds
- Parameters (sanitized)
- Source (EF Core)
- Timestamp
- Correlation ID for request tracing

### 6. Connection Pool Metrics and Alerts

Connection pool utilization is monitored and alerts are triggered when thresholds are exceeded.

**Alert Rules:**
```json
{
  "Alerting": {
    "AlertRules": {
      "ConnectionPoolWarning": {
        "Enabled": true,
        "Severity": "Medium",
        "ThresholdPercentage": 80,
        "Description": "Database connection pool utilization has exceeded 80%"
      },
      "ConnectionPoolCritical": {
        "Enabled": true,
        "Severity": "Critical",
        "ThresholdPercentage": 95,
        "Description": "Database connection pool utilization has exceeded 95%"
      }
    }
  }
}
```

### 7. Dashboard Integration

EF Core metrics can be visualized in monitoring dashboards:

**Prometheus Metrics:**
- `efcore_query_duration_seconds` - Query execution time histogram
- `efcore_slow_queries_total` - Total count of slow queries
- `efcore_connection_pool_size` - Current connection pool size
- `efcore_connection_pool_utilization` - Connection pool utilization percentage
- `efcore_query_failures_total` - Total count of failed queries

**Grafana Dashboard:**
A pre-configured Grafana dashboard is available at `monitoring/dashboards/efcore-monitoring.json` with:
- Query execution time trends
- Slow query count over time
- Connection pool utilization
- Query failure rate
- Top 10 slowest queries

## Configuration Reference

### EF Core Logging Configuration

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| `EfCore:Logging:Enabled` | bool | true | Enable/disable EF Core logging |
| `EfCore:Logging:LogSqlQueries` | bool | true | Log all SQL queries |
| `EfCore:Logging:LogQueryExecutionTime` | bool | true | Log query execution times |
| `EfCore:Logging:SlowQueryThresholdMs` | int | 1000 | Threshold for slow query detection (ms) |
| `EfCore:Logging:LogConnectionEvents` | bool | true | Log connection open/close events |
| `EfCore:Logging:LogParameterValues` | bool | false | Log query parameter values (security risk) |

### Health Check Configuration

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| `HealthChecks:EfCoreDbContext:Enabled` | bool | true | Enable EF Core health check |
| `HealthChecks:EfCoreDbContext:TimeoutSeconds` | int | 10 | Health check timeout |
| `HealthChecks:EfCoreDbContext:TestQuery` | string | "SELECT 1 FROM DUAL" | Query to test connectivity |
| `HealthChecks:EfCoreDbContext:CheckConnectionPool` | bool | true | Include connection pool check |

### Performance Monitoring Configuration

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| `PerformanceMonitoring:Enabled` | bool | true | Enable performance monitoring |
| `PerformanceMonitoring:SlowQueryThresholdMs` | int | 500 | Slow query threshold (ms) |
| `PerformanceMonitoring:SlowQueryLogging:Enabled` | bool | true | Log slow queries to database |
| `PerformanceMonitoring:SlowQueryLogging:MaxRecordsPerHour` | int | 100 | Max slow queries to log per hour |

## Usage Examples

### Checking EF Core Health

```bash
# Basic health check
curl http://localhost:5000/health

# Readiness check (for Kubernetes)
curl http://localhost:5000/health/ready

# Liveness check (for Kubernetes)
curl http://localhost:5000/health/live

# EF Core specific health check
curl -H "Authorization: Bearer {token}" \
  http://localhost:5000/api/monitoring/efcore/health
```

### Getting Connection Pool Metrics

```bash
curl -H "Authorization: Bearer {token}" \
  http://localhost:5000/api/monitoring/efcore/connection-pool
```

### Querying Slow Queries

```bash
curl -H "Authorization: Bearer {token}" \
  "http://localhost:5000/api/monitoring/performance/slow-queries?thresholdMs=1000&pageSize=20"
```

### Viewing Logs

```bash
# View today's logs
tail -f logs/log-$(date +%Y%m%d).txt

# Filter for EF Core logs
grep "EF Core" logs/log-$(date +%Y%m%d).txt

# Filter for slow queries
grep "Slow EF Core query" logs/log-$(date +%Y%m%d).txt
```

## Troubleshooting

### High Query Execution Times

**Symptoms:**
- Many slow query warnings in logs
- High query execution times in metrics

**Diagnosis:**
1. Check slow query logs: `GET /api/monitoring/performance/slow-queries`
2. Review query execution plans in Oracle
3. Check database server load and resources
4. Verify network latency between app and database

**Solutions:**
- Add database indexes for frequently queried columns
- Optimize LINQ queries to reduce data fetching
- Use `AsNoTracking()` for read-only queries
- Enable query splitting for complex joins
- Consider caching frequently accessed data

### Connection Pool Exhaustion

**Symptoms:**
- Connection timeout errors
- High connection pool utilization (>90%)
- Slow response times

**Diagnosis:**
1. Check connection pool metrics: `GET /api/monitoring/efcore/connection-pool`
2. Review connection pool configuration
3. Check for connection leaks (connections not properly disposed)

**Solutions:**
- Increase `MaxPoolSize` in connection string
- Ensure DbContext is properly disposed (use `using` statements)
- Reduce connection lifetime if connections are held too long
- Review long-running queries that hold connections

### Health Check Failures

**Symptoms:**
- Health check endpoint returns Unhealthy status
- Cannot connect to database

**Diagnosis:**
1. Check health check details: `GET /health`
2. Review connection diagnostics: `GET /api/monitoring/efcore/connection-pool`
3. Check database server status
4. Verify network connectivity

**Solutions:**
- Verify database server is running
- Check firewall rules and network connectivity
- Verify connection string is correct
- Check database credentials
- Review database server logs for errors

## Best Practices

### Production Configuration

For production environments, adjust logging levels to reduce log volume:

```json
{
  "EfCore": {
    "Logging": {
      "LogSqlQueries": false,
      "LogQueryExecutionTime": true,
      "SlowQueryThresholdMs": 1000,
      "LogConnectionEvents": false
    }
  },
  "Serilog": {
    "MinimumLevel": {
      "Default": "Information",
      "Override": {
        "Microsoft.EntityFrameworkCore": "Warning"
      }
    }
  }
}
```

### Monitoring Recommendations

1. **Set up alerts** for:
   - Slow queries (>1 second)
   - Connection pool utilization (>80%)
   - Health check failures
   - High error rates

2. **Monitor trends** for:
   - Average query execution time
   - Slow query count per hour
   - Connection pool utilization over time
   - Query failure rate

3. **Regular reviews**:
   - Review slow query logs weekly
   - Analyze query patterns monthly
   - Optimize frequently executed slow queries
   - Review and adjust thresholds quarterly

### Security Considerations

1. **Never log sensitive data:**
   - Keep `LogParameterValues` disabled in production
   - Ensure connection strings are masked in logs
   - Sanitize query text before logging

2. **Restrict access:**
   - Monitoring endpoints require authentication
   - Use role-based access control (AdminOnly policy)
   - Secure health check endpoints if they expose sensitive info

3. **Audit monitoring access:**
   - Log all access to monitoring endpoints
   - Track who views connection pool metrics
   - Monitor for unusual monitoring activity
