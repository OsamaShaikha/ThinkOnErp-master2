1. Executive summary

The HR module is large and technically mature: 194 endpoints in 21 controllers covering employees, organisation, attendance, shifts, leaves, short leaves, payroll, loans, end of service and the handoff to Accounting. The engineering foundations (ledgers, idempotency, optimistic locking, branch scoping, HR→Accounting outbox) are strong. The main risks are business-rule gaps rather than technical ones: termination bypassing End of Service, leave days trusted from the client, missing approval controls, and several read/report APIs that HR users need day-to-day.

What is done well

  • Effective-dated salary structures with component lines and server-side payroll explanation (run-lines/{id}/explanation) and run comparison.
  • Leave ledger with movements, sequence numbers, idempotency keys and one-to-one reversals; draft → post → unpost for year-end close, cash-out and migration.
  • Optimistic concurrency (If-Match on shifts / roster / organization, concurrency tokens on balances, loans, payroll status).
  • Clean separation HR → Accounting through a handoff with outbox/inbox, unique event keys and payment idempotency.
  • Branch-level data scoping, self-service mode and field-level access on sensitive employee fields.
  • Payroll correction runs (versioned) instead of editing approved payroll; period close / reopen with reason.
  • Geofenced mobile attendance with idempotent EventId and separate raw-event processing queue for devices.

Top 6 things to fix first

  1. Route every termination through End of Service; stop DELETE / PUT from setting TERMINATED (F1, F2).
  2. Calculate leave days on the server and block overlapping requests (F3, F4).
  3. Add maker-checker and no-self-approval rules (F5).
  4. Remove companyId from HR contracts; use the tenant (F6) and stop binding entities as request bodies (F7).
  5. Add list/report APIs: payroll runs, payslips, attendance timesheet (F8, F9).
  6. Expose AttendancePolicy and EndOfServicePolicy management (F10).

3. Issues, misunderstandings & how to fix them

Critical wrong business resultHigh control / data risk or blocking gapMedium integrity / completenessLow consistency · verified confirmed in code · verify not found in code – please confirm

F1 DELETE /api/hr/employees/{code} terminates the employee and blocks End of Service verified

Area
Business logic
Evidence
EmployeeService.DeleteEmployeeCoreAsync sets IsActive=false, EmploymentStatus=TERMINATED, TerminationDate=UtcNow, TerminationReason='Deactivated by user'. EndOfServiceService.Approve then requires EmploymentStatus=ACTIVE and no TerminationDate (line ~143) and throws.
Impact
If HR 'deletes' a leaving employee first, the final settlement can never be approved. The termination date becomes the click time (not the last working day), so payroll proration of the last month is wrong.
Fix
Termination should happen only through End of Service: (1) add POST /employees/{code}/terminate (or start EOS), (2) restrict DELETE to employees with no transactions (true draft cleanup) or rename it to /deactivate for data-entry mistakes only, (3) never set TERMINATED from DELETE.

F2 PUT employee / work-profile can set TERMINATED + TerminationDate directly verified

Area
Business logic
Evidence
UpdateEmployeeDto and UpdateEmployeeWorkDto carry EmploymentStatus, TerminationDate, TerminationReason and IsActive; CreateEmployeeDto also accepts EmploymentStatus/TerminationDate on create.
Impact
Same effect as above: bypasses the EOS workflow, creates terminated employees without settlement, and makes the EOS approve guard fail.
Fix
Remove TerminationDate/Reason and the TERMINATED value from editable DTOs; force EmploymentStatus=ACTIVE (or PROBATION) on create; status changes only via dedicated actions (suspend, reactivate, terminate).

F3 Leave request trusts DaysRequested sent by the client verified

Area
Data integrity
Evidence
LeaveService.SubmitLeaveRequestCoreAsync only checks DaysRequested > 0 and ≤ available; it never recomputes the days from StartDate/EndDate (the logic exists in CalculateLeaveDaysAsync / GET calculate-days).
Impact
An employee can submit 1 day for a 10-day range; approval deducts only 1 day from the balance and payroll/attendance see 10 days of leave.
Fix
Calculate days on the server (working days minus rest days and holidays, half-day support) and either ignore the client value or reject when it differs.

F4 No overlap check between leave requests of the same employee verify

Area
Data integrity
Evidence
Only pending-days sum and cycle checks were found (LeaveRepository.GetPendingLeaveDaysAsync). No query rejects a new request that overlaps an existing PENDING/APPROVED request (any type) or an approved short leave.
Impact
Double booking of the same days (e.g. Annual + Sick on the same date) and double balance consumption.
Fix
Before insert and before approval: reject if any PENDING/APPROVED leave of the employee intersects [StartDate, EndDate].

F5 No maker-checker / self-approval guard verify

Area
Controls
Evidence
PayrollService sets ApprovedBy without comparing to CalculatedBy; leave, loan, advance, correction and adjustment approvals do not check that the approver is not the requester / the employee himself, and approvals are not routed to the direct manager.
Impact
A payroll officer can calculate and approve his own payroll; an HR user who is also an employee can approve his own leave or loan.
Fix
Add rule: approver ≠ creator and approver ≠ employee's linked user; optionally require the approver to be in the manager chain (you already have /employees/me/team and ManagerEmployeeCode).

F6 companyId is required in query/body although the tenant already defines the company verified

Area
API design
Evidence
Endpoints with [FromQuery] long companyId (non-nullable): GET end-of-service, GET adjustments, GET payroll/periods, all GET payroll-policies, GET work-calendars, holidays, working-days-count. Bodies with CompanyId: CreatePayrollRunDto, CreatePayrollAdjustmentDto, all policy DTOs, Close/Reopen period, CreateWorkCalendarDto, CreatePublicHolidayDto. HrAccessFilter only auto-fills companyId when it is null; a missing non-nullable long arrives as 0 → 403 Forbidden.
Impact
Front-end confusion (403 instead of a validation message), redundant data, and an extra attack surface.
Fix
Remove companyId from all HR contracts and take it from the tenant context; if kept temporarily make it long? so the filter fills it.

F7 POST /api/hr/payroll/periods binds the domain entity PayrollPeriod directly verified

Area
Security
Evidence
PayrollController.CreatePeriod([FromBody] PayrollPeriod period).
Impact
Over-posting: client can send Id, Status (e.g. CLOSED), CreationUser, CreationDate, CompanyId.
Fix
Introduce CreatePayrollPeriodDto (PeriodCode, NameAr, NameEn, FiscalYear, Month, StartDate, EndDate, PayDate, PayrollType) and set the rest on the server.

F8 No list endpoint for payroll runs and no payslip verified

Area
Missing API
Evidence
PayrollController has GET {id}, but no GET /api/hr/payroll?period=&branchId=&status=. No payslip (PDF or JSON) endpoint and no employee self-service 'my payslips'.
Impact
The UI cannot show the runs of a period without knowing the id; employees cannot see payslips.
Fix
Add GET /payroll (paged, filters), GET /payroll/{id}/lines/{employeeCode}/payslip (PDF) and GET /payroll/me/payslips (selfService).

F9 No timesheet / attendance history read API verified

Area
Missing API
Evidence
AttendanceController exposes only today-status; HR_ATTENDANCE_DAY has no list endpoint.
Impact
HR cannot review monthly attendance, absences, late minutes or overtime before payroll; employees cannot see their own history.
Fix
Add GET /attendance/days?employeeCode=&from=&to=&status= (selfService), daily branch report (present/absent/late), and monthly summary per employee.

F10 AttendancePolicy and EndOfServicePolicy have no management API verified

Area
Missing API
Evidence
Entities AttendancePolicy (grace minutes, early-leave tolerance, overtime minimum, missing-punch handling, geofence action) and EndOfServicePolicy (severance rates, resignation factors, notice days) are used by AttendanceCalculationEngine and EndOfServiceCalculationEngine but no controller exposes them.
Impact
These business rules can only be changed by SQL; no audit and no UI.
Fix
Add /api/hr/attendance/policies and /api/hr/end-of-service/policies (GET list, GET by id, POST new effective-dated version, deactivate).

F11 Employee → Department / Position / Manager / Branch are not database foreign keys verified

Area
Relations
Evidence
Validated only in EmployeeOrganizationValidator and only when those fields change (comment: 'Unchanged legacy links are reviewed separately'). HR_DEPARTMENT / HR_POSITION are ExcludeFromMigrations with no FK; Department.ParentDepartmentCode, ManagerEmployeeCode, Position.ReportsToPositionCode are also unlinked.
Impact
Imports, SQL scripts or legacy data can create orphan codes; deactivated departments still referenced.
Fix
Add DB FKs (Restrict) or at least a nightly integrity check endpoint; validate on every save, not only on change.

F12 Pay period is a free string instead of a relation verified

Area
Relations
Evidence
PayrollRun.PayPeriod, PayrollAdjustment.PayPeriod, LoanRepaymentSchedule.PayPeriod, EmployeeAdvance.TargetPayPeriod, LeaveCashoutSettlement.PayPeriod are 'yyyy-MM' strings; PayrollPeriod has Id + PeriodCode + CompanyId.
Impact
Runs/adjustments can point to a period that does not exist or is closed; no referential protection when a period is changed.
Fix
Make PeriodCode unique per company and add FK (CompanyId, PeriodCode), or switch to PayrollPeriodId.

F13 Wrong delete behaviour on history tables verified

Area
Relations
Evidence
Employee → SalaryStructure CASCADE, Employee → LeaveBalance CASCADE, Employee → Dependents CASCADE, while LeaveRequest / Loans / PayrollRunLine are RESTRICT.
Impact
A physical delete of an employee would silently erase salary history and leave balances (latent today because delete is soft).
Fix
Change SalaryStructure and LeaveBalance FKs to RESTRICT (keep cascade only for pure child lines like SalaryStructureLine, PayrollRunLineComponent).

F14 Missing FKs / unique keys on attendance & payroll link columns verify

Area
Relations
Evidence
No FK configured for: AttendanceDay → Employee / WorkCalendar / Shift; EmployeeShiftAssignment → Employee / Shift; AttendanceCorrection → Employee; RawAttendance → Employee; PayrollAdjustment.PayrollRunLineId; LoanRepaymentSchedule.PayrollRunLineId / ReservedByHandoffId; PayrollRun.JournalVoucherId. No unique index (EmployeeCode, AttendanceDate) on HR_ATTENDANCE_DAY found in the EF model.
Impact
Orphans and possible duplicate attendance days for the same employee/date.
Fix
Add the FKs and UX_HR_ATTENDANCE_DAY_EMP_DATE (verify first whether the DB already has them outside EF).

F15 Master data keyed by code only and company derived from branch verify

Area
Multi-company
Evidence
HR_EMPLOYEE (PK EmployeeCode), HR_DEPARTMENT, HR_POSITION, HR_LEAVE_TYPE, HR_SALARY_COMPONENT, HR_SHIFT_SCHEDULE have no CompanyId. The Employee/Department query filter allows rows with BranchId = NULL for every company in the schema.
Impact
If one tenant schema hosts more than one company: duplicate codes are impossible and NULL-branch employees/departments leak between companies.
Fix
If the model is one schema per company, document it. Otherwise add CompanyId to masters, make keys (CompanyId, Code) and make Employee.BranchId mandatory.

F16 Incomplete CRUD on several resources verified

Area
Missing API
Evidence
Salary components: no GET by code / PUT / deactivate. Work calendars & holidays: no update / delete. Payroll policies (overtime, proration, SSC, tax, deduction): only add + list, no get-by-id / update / end-date / deactivate. Dependents: no update. Leave requests, loans, advances, attendance corrections: no GET by id. Loans & advances: no reject (only cancel). Departments / positions: no deactivate/delete endpoint.
Impact
Users must create duplicates instead of correcting data; approvers cannot open a single request.
Fix
Add the missing operations; for effective-dated policies use 'new version + end-date previous' instead of update.

F17 Legacy PayrollPostingConfigurationsController should be removed verified

Area
API design
Evidence
PUT always returns 409 HR_ACCOUNTING_HANDOFF_REQUIRED; GET duplicates /api/accounting/hr-handoffs/payroll-posting-config/{branchId}; controller lacks ApiExplorerSettings so it appears outside the HR Swagger group and is AdminOnly.
Impact
Dead endpoint confuses front-end and testers.
Fix
Delete the controller (or mark [Obsolete] and hide from Swagger).

F18 Position headcount is stored but never enforced verified

Area
Business logic
Evidence
HrPosition.Headcount is only written in OrganizationRepository.Writes; no check when assigning employees and no vacancy report.
Impact
Positions can be over-filled; no basis for manpower planning.
Fix
Validate on assign (warn or block per setting) and expose GET /organization/positions/{code}/occupancy.

F19 Employee status model too narrow verified

Area
Business logic
Evidence
EmployeeProfileRules allows only ACTIVE / SUSPENDED / TERMINATED.
Impact
No PROBATION, NOTICE_PERIOD, ON_LONG_LEAVE, RESIGNED; probation is only a date.
Fix
Extend statuses and drive them by actions (confirm probation, start notice, return from leave).

F20 Two sources of weekly rest days and no employee ↔ calendar link verified

Area
Business logic
Evidence
Shift has WorkingDaysJson; WorkCalendar has days; holidays can be per branch; AttendanceDay stores WorkCalendarId but employees/branches are not assigned to a calendar (only IsDefault per company).
Impact
Rest-day / working-day count may differ between leave days calculation, attendance and payroll proration.
Fix
Document one precedence rule (roster day > shift > calendar) and add calendar assignment per branch (or employee).

F21 Loans and advances have no eligibility rules verified

Area
Business logic
Evidence
LoanDeductionService validates amounts/currency only; no check on probation, active status, max installment % of salary, number of open loans, or max advance % of basic.
Impact
Requests that payroll later caps and carries forward (DeductionPolicy) — loans stretch indefinitely.
Fix
Add a LoanPolicy (max principal, max installment %, min service months, max concurrent loans) checked at application and approval.

F22 Duplicate employee update paths verified

Area
API design
Evidence
PUT /employees/{code} (full) overlaps with /work-profile, /bank, /identity.
Impact
Two ways to change the same field; harder to apply field-level permissions and audit consistently.
Fix
Keep the granular endpoints; make the full PUT internal or remove it.

F23 Inconsistent conventions verified

Area
API design
Evidence
Paging pageIndex/pageSize vs page/size; ids long vs codes; reason in body vs query (unpost adjustment uses ?reason=); approve with body (adjustments) vs no body (loans, payroll, EOS); cancel leave route requests/{employeeCode}/{id}/cancel while process is requests/{id}/process; POST departments/{code} puts the key in the URL on create.
Impact
Harder front-end integration and documentation.
Fix
Adopt one style guide: page/size, body for reasons, POST /collection with code in body, uniform action routes.

F24 Permission mapping inconsistencies verified

Area
Permissions
Evidence
Short leave submit is not selfService while leave submit is; short leave cancel needs 'reverse' while leave cancel needs 'edit'; salary structure assignment and dependents use hr-employees:create (salary is sensitive); payroll calculate & close period use 'edit'; departments/positions use hr-employees:configure.
Impact
Employees cannot request short leave from self-service; salary visibility cannot be separated from employee data entry.
Fix
Make short-leave submit selfService; add a dedicated hr-salary screen; align cancel/approve features across modules.

F25 Unknown employee code returns 403 instead of 404 verified

Area
API design
Evidence
HrAccessFilter forbids when employeeCode does not exist in scope.
Impact
Intentional for data hiding, but the front-end must show a meaningful message.
Fix
Document it in Swagger (403 = not found or not allowed).

F26 Leave request model gaps verified

Area
Business logic
Evidence
No half-day / hourly unit on LeaveRequest, no delegate/backup employee, single-level approval, attachment is only a free text reference.
Impact
Common HR scenarios (half day, sick note upload, multi-level approval) not covered.
Fix
Add DayPortion (FULL/AM/PM), DelegateEmployeeCode, document upload via file service, configurable approval chain.
