يمتاز نظام ThinkOn ERP بالفصل الذكي بين نوعين من العمليات: فواتير وحركات المستودعات التجارية المصممة لإدارة عقود التوريد، والبيع الآجل للشركات، والتصنيع، والتسويات الجردية الدقيقة، وبين فواتير نقاط البيع (POS) فائقة السرعة والمصممة للتعامل مع الزبائن، الورديات، الطاولات، التوصيل، الدفع المجزأ، والعمل بدون إنترنت (Offline Mode) مع التوافق التام مع متطلبات هيئة الزكاة والضريبة والجمارك (ZATCA).

📦 الفواتير والمستندات في المستودعات (Inventory / Commercial Transactions)

TrxDocumentHeader & TrxDocumentLine

المعمارية البرمجية الأساسية

تُبنى الفواتير المخزنية على جدولين مركزيين:
TrxDocumentHeader: رأس الفاتورة الذي يحمل بيانات الفرع، السنة، النوع، الطرف التجاري (عميل/مورد)، المستودع، العملة، ومجاميع المبالغ والضرائب والربحية والتكلفة.
TrxDocumentLine: سطور الأصناف مع معامل الوحدة، التكلفة والربح، رقم الوجبة/التشغيلة، والسيريال.

دورة حياة المستند المخزني

1. Draft (مسودة - كود 1):

قابلة للتعديل والحذف وتغيير الأسعار والكميات. لا تؤثر إطلاقاً على رصيد المخزون أو دفتر الأستاذ العام.

2. Posted (مُرحّلة - كود 3):

تصبح غير قابلة للتعديل نهائياً (Immutable). تولد حركات في InvStockLedgerEntry، وتحسب التكلفة اللحظية، وتفكك أطقم الـ BOM، وتنشئ القيد المحاسبي المتوازن.

🛒 الفواتير في نقاط البيع (Point of Sale - POS Invoices & Orders)

PosOrderHeader & PosOrderPayment & PosEInvoicing
⚡

طبيعة الفاتورة اللحظية

تتميز فواتير الـ POS بالسرعة القصوى، وترتبط تشغيلياً بـ: الوردية المفتوحة (PosShift)، نقطة الكاشير (PosTill)، الطاولة والرواد (PosTable / Covers)، وأنواع الطلب (صالة Dine-in، سفري Takeaway، توصيل Delivery).

حالات الطلب (Order Statuses):
Draft (قيد التجهيز) Parked (معلق) Completed (مكتمل) Refunded (مسترجع)
💳

الدفع المجزأ والعمل دون إنترنت

تدعم فاتورة نقاط البيع السداد بأكثر من وسيلة دفعة واحدة عبر PosOrderPayment: (جزء نقد + جزء شبكة/فيزا + نقاط ولاء + بطاقات هدايا + ذمم عملاء).

المرونة في انقطاع الشبكة (Offline Resilience):

يتم حفظ الفاتورة محلياً مع مفتاح ClientUuid. وعند عودة الاتصال، يمنع النظام التكرار، وفي حال وجود عجز بالمخزون يُنشئ حركة صراع PosInventoryConflict للمراجعة الإدارية.

📑

الفوترة الإلكترونية والإقفال (Z-Report)

متوافقة 100% مع هيئة الزكاة والضريبة والجمارك (ZATCA): توليد QR Code فوري بنظام TLV Base64 يحتوي اسم البائع، الرقم الضريبي، التاريخ والوقت، إجمالي الفاتورة، ومبلغ الضريبة، مع توليد الهاش الرقمي المشفر InvoiceHash.

الترحيل المجمع لدفتر الأستاذ:

عند نهاية اليوم يتم إنشاء تقرير PosZReport الذي يُلخص إيرادات الوردية، ويُطابق النقد الفعلي مع المتوقع، ويرحل قيد اليومية العام GlVoucherId دفعة واحدة.

🛡️ منظومة قواعد التحقق الشاملة (100% Zero-Error Validation Suite)

القواعد الإلزامية في طبقتي التطبيق وقاعدة البيانات لمنع أي خطأ بشري أو تقني وضمان صحة الفواتير محاسبياً وضريبياً 100%.

32 قاعدة رقابية صارمة

1 التحقق من رأس الفاتورة والفترة المحاسبية والوردية (Header & Session Validations)

5 قواعد
الكود قاعدة التحقق الشرط البرمجي (Validation Rule) الإجراء عند المخالفة
V-H01 الفترة المالية المفتوحة DocDate in Active GlFiscalPeriod AND Status == Open رفض الحفظ (الفترة مقفلة مالياً)
V-H02 الوردية النشطة (POS) Shift.Status == PosShiftStatus.Open AND Shift.TillId == TillId منع البيع بدون وردية مفتوحة
V-H03 منع التكرار (Idempotency) UniqueIndex(BranchId, ClientUuid) AND UniqueIndex(BranchId, DocNo) إرجاع الفاتورة المسجلة دون تكرار
V-H04 سعر صرف العملات CurrencyCode != BaseCurrency => ExchangeRate > 0 منع سعر صرف صفري أو سالب
V-H05 تطابق الفرع والمستودع FromWarehouse.BranchId == Document.BranchId رفض الصرف من مستودع فرع آخر

2 التحقق من الأطراف والرقابة الائتمانية والذمم (Party & Credit Control)

4 قواعد
الكود قاعدة التحقق الشرط البرمجي (Validation Rule) الإجراء عند المخالفة
V-P01 إلزامية العميل في الآجل PaymentMethod == Credit => PartyId != null AND PartyId != WalkInCustomer حظر البيع الآجل لعميل نقدي عام
V-P02 سقف الائتمان (Credit Limit) (Customer.CurrentBalance + TotalNet) <= Customer.CreditLimit إيقاف الفاتورة وطلب إذن مالي
V-P03 حظر الفواتير المتأخرة Count(OverdueInvoices where DueDate < Today - GraceDays) == 0 تجميد البيع للعميل لحين سداد المتأخر
V-P04 منع تكرار فاتورة المورد Unique(VendorId, VendorInvoiceNumber) in PurchaseBills منع دفع الفاتورة مرتين للمورد

3 التحقق من سطور البنود والمخزون والتتبع (Stock & Traceability Validations)

6 قواعد
الكود قاعدة التحقق الشرط البرمجي (Validation Rule) الإجراء عند المخالفة
V-L01 إيجابية الكميات Quantity > 0 (فواتير عادية) | Quantity < 0 (فواتير مردودات فقط) منع كميات صفرية أو سالبة غير مبررة
V-L02 منع البيع بالسالب (Negative Stock) Quantity <= (StockBalance.OnHandQty - StockBalance.ReservedQty) رفض الصرف منعاً لانهيار التكلفة
V-L03 التشغيلات والصلاحية (FEFO/FIFO) Item.IsLotTracked => LotNumber != null AND ExpiryDate > Today منع صرف مواد منتهية الصلاحية
V-L04 الأرقام التسلسلية (Serials) Item.IsSerialTracked => Count(Serials) == Quantity AND Status == InStock منع بيع أجهزة بدون سيريال فريد
V-L05 معاملات تحويل الوحدات (UoM) BaseQuantity == Quantity * UomConversion.Factor منع خطأ ضرب تحويل الكراتين لحبات
V-L06 خيارات المعدلات الإلزامية (POS) Grp.IsRequired => SelectedCount >= MinSelections && <= MaxSelections منع إضافة الصنف حتى اكتمال خياراته

4 التحقق من الأسعار والخصومات وهوامش الربح (Pricing & Margin Control)

4 قواعد
الكود قاعدة التحقق الشرط البرمجي (Validation Rule) الإجراء عند المخالفة
V-M01 الحد الأدنى لسعر البيع UnitPrice >= PriceListItem.MinPrice حظر البيع بأقل من الحد الأدنى
V-M02 منع البيع بأقل من التكلفة UnitPrice >= UnitCost (مستودعات وتجزئة) تحذير حرج وحظر إلا بموافقة المدير
V-M03 سقف الخصم وصلاحيات المستخدم DiscountPercent <= User.MaxAllowedDiscountPercent منع الخصومات العشوائية غير المصرحة
V-M04 منع الخصم السالب أو الزائد DiscountAmount >= 0 AND DiscountAmount <= (Quantity * UnitPrice) منع أن يصبح صافي السطر سالباً

5 التحقق من المعادلات الرياضية والضرائب (Mathematical & Tax Precision)

4 قواعد
الكود قاعدة التحقق الشرط البرمجي (Validation Rule) الإجراء عند المخالفة
V-T01 مطابقة معادلة السطر LineTotal == Round((Qty * Price) - Discount + TaxAmount, 2) إعادة الحساب بالباك إند وتصحيح الكسر
V-T02 مطابقة مجاميع الرأس للسطور Header.TotalGross == Sum(Lines.LineGross) && Header.Tax == Sum(Lines.Tax) رفض الحفظ عند وجود تفاوت > 0.01
V-T03 الشمول الضريبي (Inclusive) TaxInclusive => TaxableBase = LineTotal / (1 + (Rate / 100)) منع ازدواجية احتساب الضريبة
V-T04 الرقم الضريبي للمنشأة Seller.VatNumber.Length == 15 AND StartsWith('3') AND EndsWith('3') حظر إصدار الفاتورة الضريبية ZATCA

6 التحقق من السداد وتطابق المقبوضات (Settlement & Payments)

3 قواعد
الكود قاعدة التحقق الشرط البرمجي (Validation Rule) الإجراء عند المخالفة
V-S01 كفاية المدفوع في النقدي Sum(Payments.Amount) >= TotalAmount => Change = Paid - Total منع إنهاء الفاتورة النقدية برصيد معلق
V-S02 مراجع البطاقات الإلكترونية PaymentMethod == Card => TransactionReference != null || TerminalId != null منع دفع شبكة وهمي بدون إيصال
V-S03 صلاحية ورصيد بطاقات الهدايا GiftCard.IsActive && ExpDate > Now && RedeemedQty <= CurrentBalance رفض بطاقات الهدايا المنتهية أو الفارغة

7 التحقق من المردودات والإلغاء (Refunds, Returns & Void Control)

3 قواعد
الكود قاعدة التحقق الشرط البرمجي (Validation Rule) الإجراء عند المخالفة
V-R01 الارتباط بالفاتورة الأصلية Refund.OriginalOrderId != null AND OriginalOrder.IsPaid == true منع استرجاع فاتورة وهمية أو غير مدفوعة
V-R02 سقف الكمية المرتجعة QuantityToRefund <= (OriginalSoldQty - TotalPreviouslyRefundedQty) منع استرجاع كمية تزيد عما اشتراه العميل
V-R03 تدقيق إلغاء السطور (Void Audit) VoidLine => Reason != null AND ApprovedBySupervisor != null تسجيل أمني كامل لمحاولات الإلغاء لمنع السرقات

8 التحقق من الترحيل المحاسبي والفوترة الإلكترونية (Posting & ZATCA Compliance)

3 قواعد
الكود قاعدة التحقق الشرط البرمجي (Validation Rule) الإجراء عند المخالفة
V-A01 توازن القيد المحاسبي المتولد Sum(GlVoucherDetails.Debit) == Sum(GlVoucherDetails.Credit) فشل الترحيل الفوري في حال عدم التوازن
V-A02 منع التعديل بعد الترحيل DocStatusCode == 3 (Posted) => IsReadOnly (Update/Delete Disabled) إغلاق السجل واعتماد إشعار تسوية فقط
V-A03 سلامة الـ Hash والـ QR Code EInvoiceHash == ComputeSha256(XML) AND TLV QR Base64 Valid رفض الاعتماد لمخالفة معايير هيئة الزكاة

💻 نموذج برمجي تطبيقي (FluentValidation Implementation)

كود جاهز للتطبيق في طبقة التطبيق ThinkOnErp.Application لضمان الرقابة الصارمة

C# • FluentValidation 
public class CreateTrxDocumentDtoValidator : AbstractValidator<CreateTrxDocumentDto>
{
    public CreateTrxDocumentDtoValidator()
    {
        // 1. Header Validations
        RuleFor(x => x.BranchId).GreaterThan(0).WithMessage("معرف الفرع إلزامي وصحيح");
        RuleFor(x => x.DocYear).InclusiveBetween(2020, 2050).WithMessage("السنة المالية غير صالحة");
        RuleFor(x => x.DocDate).NotEmpty().LessThanOrEqualTo(DateTime.UtcNow.AddHours(24))
            .WithMessage("تاريخ المستند لا يمكن أن يكون في المستقبل البعيد");

        // 2. Party & Credit Validations
        When(x => x.PaymentMethodCode == 2 /* Credit */, () => {
            RuleFor(x => x.PartyId).NotNull().GreaterThan(0)
                .WithMessage("العميل إلزامي في حالة البيع الآجل، ولا يُسمح بالعميل النقدي العام");
        });

        // 3. Lines Integrity
        RuleFor(x => x.Lines).NotEmpty().WithMessage("يجب أن تحتوي الفاتورة على سطر صنف واحد على الأقل");
        RuleForEach(x => x.Lines).ChildRules(line =>
        {
            line.RuleFor(l => l.ItemId).GreaterThan(0).WithMessage("معرف الصنف إلزامي");
            line.RuleFor(l => l.QuantityOut).GreaterThan(0).When(l => l.QuantityIn == 0)
                .WithMessage("الكمية المصروفة يجب أن تكون أكبر من الصفر");
            line.RuleFor(l => l.UnitPrice).GreaterThan(0)
                .WithMessage("سعر الوحدة يجب أن يكون قيمة موجبة");
            line.RuleFor(l => l.DiscountAmount)
                .Must((l, d) => d >= 0 && d <= (l.QuantityOut * l.UnitPrice))
                .WithMessage("قيمة الخصم يجب ألا تتجاوز إجمالي السطر");
        });

        // 4. Totals Recalculation Check
        RuleFor(x => x.DiscountAmount).GreaterThanOrEqualTo(0);
    }
}
